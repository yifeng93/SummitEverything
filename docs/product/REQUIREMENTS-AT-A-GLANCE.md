# SummitEverything 需求速览（2026-10-28）

给久未回看项目时的自己，以及接手实现的 agent。完整口径仍以 [PRODUCT-SPEC](PRODUCT-SPEC.md) 为准；这里只回答「这个项目到底要干什么、现在做到哪」。

## 1. 一句话

把本机零散的工作材料，整理成**经本人确认**的 Markdown 知识，并能在本机按出处检索、问答、复用；单机可完整工作，未来能迁移、能给同事独立使用。

## 2. 为谁、解决什么

- 首要用用户本人；未来同事各自独立使用，不做团队共享编辑。
- 原始材料已有，但缺少符合本人工作习惯的「输入 → 整理 → 审核 → 确认 → 积累」固定流程；通用 prompt agent 不能替代这套流程。
- 核心资产是普通 Markdown，可与 Obsidian 等工具共存；不锁定在应用私有格式里。

## 3. 核心需求（用户已确认的 v1）

| # | 需求 | 关键约束 |
|---|---|---|
| 1 | 组织知识 | 线 → 项目 → 页面；页面一个主项目；分类不规定正文结构；项目总览是入口 |
| 2 | 输入 | 粘贴、TXT/Markdown 文件、文件夹批量；飞书日历/待办/材料可查看；列表和随手记不调用模型 |
| 3 | 整理 | 模型忠实重组原文，保留事实/想法/建议/未决；一份输入可生成多份稿件；默认更新权威页而不是堆重复纪要 |
| 4 | 确认 | 每份稿件独立确认；冲突展示依据；未确认不覆盖正式页；任务、项目进度、知识批准分别确认 |
| 5 | 检索问答 | 事实、跨材料比较、工作方案；回答区分来源陈述与推断/建议；引用绑定内容版本，过期要明说 |
| 6 | 本地优先 | 知识正文在工作库；索引、聊天、记忆、凭据、诊断在本机 profile；凭据进 macOS Keychain |
| 7 | 飞书 | 任务以飞书为唯一账本；应用身份优先，必要时用户授权；真实调用逐次范围预览 + 确认；结果未知不重发 |
| 8 | 交付 | 单台 Mac 的 DMG/内部 WebUI；先单机、再 5 个工作日、再双机轮流写；不做团队实时协作、PDF/OCR、工作库 Git |

成功标准：真实材料能进入正确权威页；批准与未决清晰；回答可追溯；外部修改不会继续使用过期批准；单机完整可用。

## 4. Agent 接入方向（2026-10-29 补充）

用户明确：这个项目是 **AI Agent 的前一步**，不是只服务人手点的 UI。

- 通过 MCP 暴露工具，由 Codex / WorkBuddy 在对话里询问用户后决定是否入库。
- 「会议要不要入库」不由应用写死；助手可调用日历、原件和待审稿工具辅助判断，最终正式入库仍需用户确认。
- 当前提供标准 MCP stdio 工具接口，具体行为与配置见 [MCP-v1](../contracts/MCP-v1.md)；原型仍只是设计探索，当前验收状态见 [PROGRESS](../implementation/PROGRESS.md)。
- 当前 MCP 支持原件导入和完整待审稿提交，但不开放 `page.confirm`：Agent 不能自行证明已获批准，正式内容仍由用户在应用中确认；既有会议内容规则保持不变。

## 5. 当前实现状态（据本轮实测）

| 能力 | 状态 | 证据/限制 |
|---|---|---|
| 工作库、线/项目/页、Markdown + frontmatter | 可用 | 开发库 152 页；确认页带 approval |
| 本地导入、随手记、整理、稿件、确认 | 可用（Fake） | 真实 LLM 未测 |
| 索引 | 可用 | 本机 LanceDB 0.40.0（`index.lancedb`）+ SQLite 活动代指针；152 页 / 3530 分块；中文 BM25 用 n-gram，不装词典 |
| 知识问答 | 可用，质量取决于向量 | 真实文档能命中；BM25 补上了纯向量漏掉的关键词问法（`dsh web 默认端口` 从 0 条到 5 条引用）；Fake LLM 仍只拼接片段 |
| 飞书日历/任务/材料 | 适配器与门禁有 | 真实租户未授权、未联调 |
| 真实模型/embedding/rerank | 未测 | 无密钥；当前全 Fake |
| MCP/Agent 工具层 | 标准 stdio 接口，14 个工具 | 当前验收状态见 [PROGRESS](../implementation/PROGRESS.md)；实际客户端配置另验 |
| DMG/五日/双机 | 未在本轮验证 | 需单独验收门 |

本轮真实语料测试还暴露并修复了两个检索性能问题：候选页逐页重读导致 O(n²)、planner 别名逐次正则归一化。索引迁到 LanceDB 后，同样的 152 页 / 3530 分块重建从分钟级降到 6 秒。

## 6. 知识库视图（已实现）

原来的「项目」页只有按日期排的时间线，151 篇文档铺成一条流水，看不出覆盖范围，也看不出哪些内容进了索引。

现在的结构：

1. **概览条**：已确认页 / 已索引页 / 分块 / 待更新，右侧一行状态（可用 / 待更新 / 尚未建立，并标明是仿真向量还是真实向量）。
2. **项目列表**：保持原有主线 → 项目目录，搜索、状态筛选、归档折叠不变。
3. **项目内页面按来源目录分组**：取 `source_path` 的末级目录（`docs/subsystems/x.md` → 子系统），没有来源路径的按页面类型归（推进日志 / 关联会议 / 主题）。大组在前，组内保留时间顺序。
4. **索引诊断（L3）**：chunk 标题、字数、向量维度/范数/预览用 `scripts/inspect_index.py`，不塞进主界面。

这套视图解决「索引看不到」：先看到覆盖范围和目录，再点进页面；问答只是检索入口之一。
