# SummitEverything 前端逐页规格

日期：2026-10-14。状态：**用户已确认**。配套文件：[FRONTEND-GUIDE.md](FRONTEND-GUIDE.md)（原则、tokens、守卫）、[ADR 0011](../decisions/0011-frontend-ux-baseline.md)（决策记录）。

**怎么用这份文件**：每个页面给出「区块顺序 + 每块写什么 + 三态 + 折叠项 + 不做什么 + 验收点」。
区块顺序是**规格**，不是建议：顺序变了要改这份文件并说明理由，不能顺手调。
所有页面都必须满足 GUIDE §4（文案）、§5（交互）、§6（样式）、§7（排版）、§9（细节分级）。

图例：**L1** = 主界面可见；**L2** = `<details>`「本次详情」/「技术信息」；**L3** = 只在诊断导出。

## 0. 应用外壳（`App.tsx` + 新 `components/AppShell.tsx`）

### 职责
让用户随时知道自己在哪、这个应用现在是什么状态、怎么换工作库。壳不承载业务。

### 结构（自上而下 / 自左向右）

1. **左侧栏（200px，`--sidebar` 背景）**
   - 品牌区：图标 + `SummitEverything` + 副标题「个人知识工作台」。副标题在 ≤640px 隐藏。
   - 主导航（恰好 5 项，顺序固定）：
     `今日` / `审批` / `项目` / `知识问答` / `设置`
     - 每项高 32px（与二级菜单行高一致，hover / 选中的高亮带同高），图标 18px + 文案 14px，当前项 `background: var(--sidebar-active)` + 左侧 3px 强调条 + `aria-current="page"`；粗指针与 ≤560px 底栏仍抬到 ≥44px。
     - **审批**项带数量徽章（待处理总数，`--danger` 底 + `--on-accent` 字）；为 0 时不显示徽章。
   - **「项目」二级入口**：紧跟在「项目」下方，列出未归档项目的名称，点一下直接打开该项目详情。
     - 只列名称，12px，单行省略；与「项目」文案左对齐（缩进 28px）。
     - 当前打开的项目 `aria-current="page"` + 左侧 2px 强调条；不再填充背景，避免与父项抢层级。
     - 二级项**不是**第 6 个导航目的地，不计入 5 项；≤800px 图标栏与 ≤560px 底栏不显示。
     - 项目为空时不占位；项目新建/重命名/归档后随目录刷新。
     - 点一级导航「项目」永远回到**项目列表**：即使当前停在某个项目详情或文档正文，这一下也退回列表；打开具体项目只能用二级入口或列表行。
   - 底部：保存状态（真实三态：`已保存` / `保存中…` / `保存失败，点击重试`，仅在非空闲时占位）+ 紧凑工作库选择器（首字头像 + 当前名称 + 上下箭头），点开菜单后选「切换工作库」；下方「外观」入口，点开弹出 `跟随系统 / 浅色 / 深色` 三选。不再常驻「仅本机运行」提示；服务不可达时用专门错误页说明。
2. **没有顶栏**：不再用 62px 的条重复当前页名；页名由各页自己的 `h1` 承担，面包屑只出现在页面阅读页的面包屑行。主题切换不放在顶部。
   - 保存三态从顶栏移到侧栏底部（≤800px 图标栏与 ≤560px 底栏不显示）。
   - 删除硬编码头像「罗」与永远为真的「本机已保存」。
3. **主内容区**：`max-width: 1200px` 居中，页头（`h1` + 右侧动作）+ 各页区块。页面与区块标题下不再放解释性副标题（GUIDE §4.1）。页头、卡片、分隔线共用同一条左右边线：需要收窄的只有正文行宽（`--measure-read`），不要给卡片或整块单独设 `max-width`，否则右边线会参差；带分隔线的正文块要在整块上画线，只收窄内部文字。
4. **全局提示**：不再有一个常驻的红色横幅。错误走 toast（失败色）；需要停顿的错误用可关闭的就地提示块。

### 三态
- 加载：首屏显示"正在连接本机服务…"，**不显示**工作库向导。
- 错误：本机服务不可达时显示专门的就地页面/提示块：一句白话 + 「重试」+ 「查看日志目录」（L2 里给路径）；**不得**把它当成"还没有工作库"而弹出首次配置。
- 空（真的没有工作库）：才进首次配置向导。

### 不做什么
- 不做顶部页签改造（D5）。
- 不给「日志与思考」「飞书日常」留导航项；不加第 6 项。
- 不用 `⌄` 暗示不存在的下拉菜单。

### 验收点
- 导航恰好 5 项、标签精确、顺序固定；当前项有 `aria-current="page"`。
- ≤800px 折成 64px 图标栏，每个图标有 `title` + `aria-label`；≤560px 变底部 5 栏（每项 ≥44px）。
- 本机服务 500 时显示错误页而不是向导（对应守卫 ④ 的变体）。

## 1. 首次配置向导（App 统一宿主；复用 `WorkspaceGate.tsx` 与 `FirstUseWizard.tsx` 步骤组件）

### 职责
在一个流程里打开工作库、配置模型与密钥、检查连接并授权飞书。无工作库时先显示第 1 步；其它首次配置入口仍使用同一向导。今日和设置主区的「连接飞书」改为复制助手提示词，手动配置保留在高级 / 兼容区。流程完成后不自动打扰，用户仍可从设置手动进入对应步骤。

### 结构（5 步，一条流程，可跳过、可中断续接）

**页头**：`SummitEverything` 标记 + 步骤指示（1–5，`aria-current="step"`）+ 「稍后再说」（跳过当前步）+ 「关闭」（退出向导，未完成也不阻塞浏览；第 1 步关闭回欢迎连接页，打开工作库后关闭回来源业务页）。
**主区**：当前步的内容，一次只显示一步。
**页脚**：`上一步` + 主操作（每步一个 `.button.primary`）。

| 步 | 标题 | 内容 | 主操作 |
|---|---|---|---|
| 1 | 新建 / 打开工作库 | 无外层卡片；品牌行与标题居中，表单为页面中央一列（约 400px）。标题随模式变为「新建工作库」或「打开工作库」。只有三段：模式分段（新建 / 打开已有）、工作库名称（仅新建）、文件夹路径。**用原生目录选择器**（macOS 里就是「选择…」）；浏览器预览环境允许粘贴完整路径。不出现步骤说明、装饰性大标题、隐私脚注或路径示例说明。成功打开后在同一流程原地进入第 2 步。 | 「创建本地工作库」/「打开工作库」 |
| 2 | 模型与密钥 | 整理与问答固定为 DeepSeek；检索固定为本地 BGE 模型，不显示 Fake/Mock 或云端 embedding / rerank provider。必须配置 DeepSeek 密钥；本地模型下载不在本步隐式开始。`type="password"` 字段只在内存中，成功保存/退出后清空；可稍后完成配置，但不能切换到模拟 provider。 | 「保存并继续」 |
| 3 | 检查连接 | 仅 DeepSeek 提供固定短合成连接检查；点击后弹 `SmokeCheckConfirm`，由用户确认后发送。本地索引模型只读本机状态，不做云端 smoke。 | 「继续」 |
| 4 | 连接飞书 | 首次配置向导仍可按既有流程授权；今日和设置主连接入口复制助手提示词。**非秘密接入值（App ID / callback / Base URL）不在这一步出现**（在设置高级区）。 | 「继续」 |
| 5 | 完成 | 汇总：工作库名、模型状态、飞书状态；以及一句话边界（"没做完的可以随时在设置里继续。"）。列出被跳过的步骤，各带一个"现在去补"入口。 | 「开始使用」→ 进入今日 |

### 三态
- 加载：读取本机设置时显示"正在读取本机设置…"（沿用现有诚实加载态）。
- 错误：字段级错误贴字段；连接失败显示原因白话 + 下一步（沿用 `settingsBadges.ts` 的映射，例如"账号还没有这个应用的使用权限 → 找管理员加进可用范围"）。
- 空：不适用（向导本身是空态入口）。

### 折叠项（L2）
- 第 1 步：工作库完整路径、库标识。
- 第 3 步：「本次详情」= 端点、模型名、请求次数上限、累计剩余次数。
- 第 4 步：正常流程不展示技术回调、App ID；设置高级区可查看必要的接入信息。
- L3：只进「设置 → 高级与自定义 → 诊断导出」。

### 不做什么
- 不把向导做成两条割裂流程（App 统一宿主持有步骤；工作库入口复用 gate 的表单逻辑，打开后原地进入后续步骤）。
- 不要求用户手敲 `/Users/you/...` 这类路径（原生选择器优先）。
- 第 1 步不放大标题、步骤口号、隐私说明或「先打开工作库…」的提示块；只留模式、名称、路径与主按钮。
- 不用"通知"代替必填校验。
- 不在保存后自动联网验证。
- 密钥不写入 localStorage / sessionStorage / 工作库；`type="password"` + `autoComplete="new-password"`，提交成功后立即从 state 清空。

### 验收点
- 在第 3 步且向导仍打开时页面重载，自动恢复第 3 步；恢复键由服务端返回的真实 profile + workspace 身份组成，不猜身份。
- 用户显式关闭后重载不自动弹；从设置手动继续可回到第 3 步。完成后重载不自动打开。
- 必填缺失时主按钮禁用，且 `title` 说明缺什么；已有凭据不重复要求录入。
- 所有入口只打开同一向导宿主；"稍后再说"跳过的步骤在设置页有对应入口。
- 首屏（服务可达、无工作库）先显示"正在连接…"，随后才进向导；服务报错时显示错误页而不是向导。

## 2. 今日（`components/TodayView.tsx`）

### 职责与主操作
今日让用户查看日程、任务、保存随手记录并导入材料。已授权连接后，刷新和分页直接读取有界的飞书日历，不再展示本次范围预览或二次确认；材料读取、材料导入和任务写入继续保留各自门禁。今日不编辑真实飞书任务。

### 区块顺序与布局

1. **页头**：`今日` + 右侧日期。
2. **宽屏左右两区**：左侧依次显示会议、待办任务和需要行动；右侧是「记录与导入」卡：标题行右侧放「导入材料」「工作日志 / 思考」两个次级入口，下面依次是记录输入框、保存回执和最近材料。窄屏纵向排列，日程/任务在记录区之前。
3. **会议与任务**：若 status 证明日历身份有有效 scope 且 access 可用或可续期，进入今日后自动发起一次只读日历读取；StrictMode 并发合并，失败不自动循环重试。手动刷新即读取所选时间范围，最多读取一个有界结果页，真实接口不支持该范围分页时保留截断提示。默认最多 3 条；任务默认最多 5 条。各自可展开全部已读取结果，并保留原有分页入口。时间与状态使用紧凑但可读的显示；失败保留上次成功结果和时间，首次失败不可伪装成空态。刷新这类明确动作一律用图标按钮（`aria-label` 写全，最近读取时间放 `title`），不占一行文字。
4. **随手记录**：输入框按原文保存，不触发模型；动作行只保留「保存原文」一个主按钮，靠右对齐、不换行。保存后显示实际回执和准确材料 ID 对应的继续整理入口。
5. **导入材料**：打开独立导入抽屉；多项结果按 API 返回的成功 `item_id` 定位。已经 processing/reviewing 的来源继续使用现有任务/稿件，不重复创建 job。
6. **近期材料**：呈现真实保存结果、材料状态及可信来源类型；不按文件名猜来源类型。标题行右侧只留「全部材料」（文字）与一个刷新图标按钮；读取成功不显示时间戳，失败才在标题下写明原因并保留已有内容。工作日志/思考继续在独立工具弹层中处理；确认记录已保存后关闭弹层，并通过外层提示给出保存回执，保存失败则保持弹层和已输入内容。

### 三态与限制

- 加载、成功空态和错误分开呈现；单个来源失败保留该来源的最近成功值。
- 状态把有效 access、过期但可续期的授权、需重新授权分开显示；status 只读本机凭据，不刷新 token。需重新授权时今日页提供「连接飞书」提示词复制入口，不弹向导、不发 OAuth 或外部请求；剪贴板拒绝时提供可选文本和重试。状态不得只凭 App ID 显示为可用。日历读取仅在身份、有效 scope 和当前工作库均通过服务端校验后执行；过期但可续期的 access token 由日历读取续期并保存，单次刷新有请求/时间/响应大小上限，失败不自动重试并保留错误态。
- 不把待整理队列、审核稿或正式内容审批搬到今日；项目进度变化与飞书写入仍需独立确认。

### 验收点

- 1280×800 非空首屏同时可见会议标题与首条会议、任务标题与首条任务、记录输入和导入入口。
- 4 场会议默认只展示 3 场；6 项任务默认只展示 5 项；展开后全量可达，原有分页仍可用。
- 保存/导入回执使用服务实际返回的 ID；同名材料不得错位；重复点击不为已有 processing/reviewing 来源创建第二个 job。
- 五栏导航、窄屏无横向溢出和无位置误导文案继续通过既有守卫。

## 3. 审批（`components/ApprovalView.tsx`）

搜索准备状态的交互决策见 [ADR 0030](../decisions/0030-search-readiness-approval-ux.md)。

### 职责与结构
将来源整理、稿件复核、正式内容确认、索引和外部动作分开处理，固定五组顺序（来源 → 稿件 → 正式内容 → 索引 → 外部动作）。这五组是**并列的待办队列，不是步骤**：按流水线顺序摆放，但可以任意顺序处理，因此**不标 1/2/3 序号**——序号会被读成操作步骤，和实际业务不符。每组显示真实数量、加载/错误/空状态；有待处理事项的组默认展开，空组默认收起且可展开，用户选择的展开状态在打开和返回单项专注页后保留。

**布局**：五组是**同样大小**的卡片，固定三列（第三行自然留白，不为了填满而改宽度），每张高 420px；内容超出时在卡内滚动，卡片本身不撑高、不改变列宽。卡片里是「标题 + 一句说明 + 数量」，内容直接可见，没有折叠。≤800px 单列、高度自适应。

各组最近成功读取时间显示在头部说明后并允许窄屏换行；无说明的「搜索与问答准备」放在标题下方。读取失败时仍在头部显示上次成功时间，正文只保留错误、旧内容提示和重试；外部动作组仅在两个资源都成功读取过时显示二者中较早的成功时间。

### 来源

- 来源行**整行就是入口**：点一下在弹层里看原文、选主线/项目、点「整理」。不设勾选框，也没有底部批量条——单条流程更接近常规「点开一条 → 处理」。
- 点一条来源**直接在弹层里打开**（标题 + 文件名/时间/状态 + 可滚动原文 + 底部整理区），不替换清单、不跳独立页面；清单保持可见，关闭后回到原行。
- 使用来源的准确 ID 定位，不以标题或文件名猜对象；显示原文、归属与当前整理状态。
- 整理完成后列本次 job 实际生成的稿件 ID/标题并可直接打开。processing/reviewing 来源继续到现有稿件，不重复发起整理。
- 整理仍需明确主线/项目及范围确认。原件只供追溯，不进入检索。

### 稿件

- 紧凑列表点击后进入单份专注页，保留返回位置与展开状态；默认呈现渲染 Markdown。
- 编辑正文/归属、查看来源、查看改动差异是分别按需展开的区块；冲突选择在编辑/阅读期间保留。
- PATCH 未持久化冲突选项，因此“保存修改”仅保存 API 支持的正文/归属字段，并明确说明冲突选择尚未提交；选择只在用户确认最终稿件时生效。
- 对 expected_version 或目标版本冲突按 API 状态/code 识别。载入新版前保护未保存正文；用户明确选择重载后才替换。
- 确认结果保留真实 `index_update` 反馈与真实保存 page ID，提供打开正式页或下一份待审稿入口。不得对多个稿件做隐式批量确认。

### 正式内容、索引与外部动作

- 正式页面按准确 page ID 打开单项阅读专注页；确认后呈现实际回执与下一份待确认入口。
- 搜索准备区标题为「搜索与问答准备」，说明其作用是让已确认内容可用于搜索和问答。索引状态为 ready 且配置未变化时，只说明内容已是最新、展示已准备页数，不显示预览或重建入口；全量重建收在「高级维护」并由用户显式点击后才请求计划。
- 首次状态 `not_ready` 且正式页面列表已成功读取、存在 confirmed 页面时，准备组作为待处理事项计数并默认展开；是否可首次准备只依据该列表，不能用 `current_pages` 或索引内容推断。空库说明先添加并确认正式内容，不允许执行首次或全量准备。页面列表未读取或读取失败时不显示可执行首次准备入口，提供刷新。
- `stale` / `manual_required` 显示待更新并允许先看范围；configured 与 active fingerprint 不同则优先说明搜索方式已更换，并先看重新准备范围。未知状态或未读取配置时显示刷新入口，不伪装为 ready。
- 增量计划中的 `page_ids` 是服务端检查范围，可能覆盖多页；文案说「将检查 N 页，仅更新有变化的内容」，不得将它说成变化页数或计费页数。Real 预览仍先创建 acceptance-plan，范围失败时不得开放执行；用户必须再次显式确认。Fake 不创建 acceptance-plan。演示模式只说明体验流程，不暗示真实搜索语义质量已可用。
- 首次、模型变更、重建及服务标记 `manual_required` 的本地准备计划仍单独预览和确认；索引步骤使用本机模型，无外部请求计划或云端用量估算；同模型批准内容的增量依本机规则执行。
- 外部动作保持“建议—确认—执行”分离；结果未知只能核对或记录，不自动重试。

### 未保存保护与验收点

- 未保存稿件会阻止侧栏离开、打开正式页面、切换工作库和浏览器关闭；刷新其他审批数据不能清空编辑内容。
- 同名来源/正式页必须准确定位；多稿保存时只确认明确选择的那一份。
- 空组可展开且展开状态在专注页返回后保留；已有 confirmed 正式内容但首次索引未建时，真实 FastAPI Fake 流程应显示待处理数量并展开搜索准备组。
- 主界面不展示内部 ID、路径、hash 或原始 JSON；危险动作仍有独立确认。

## 6. 页面阅读页（`components/PageReader.tsx`）

### 职责
读一页知识，并决定它算不算当前正式内容。

### 主操作
状态相关的唯一主操作：待确认 → 「确认当前版本」；已确认但有新版本 → 「确认新版本」；历史版本 → 无主操作，只有「返回」。

### 结构

1. **返回行**：左「← 返回项目」/「← 返回知识」；右侧是「页面操作」（仅已确认页）与窄屏的「目录」入口。
2. **目录（左栏，桌面 224px）**：项目 → 文件夹（可多层）→ 页面；文件夹可展开/收起，当前页所在的整条路径默认展开并高亮，其余收起。节点计数是子树页数。口径复用 `page-groups.ts` 的同一棵树。视口 ≤1100px 时收成「目录」按钮，点开右侧抽屉，选中页面后抽屉自动收起。
3. **面包屑**：`项目 / 文件夹 / 子目录`，只读，不承担跳转；页面没有项目时只显示目录部分。多层结构必须逐层列出，不压平成最后一段。
4. **页头**：页面显示名 + 状态徽章（`待确认` / `已确认知识` / `已被替代`）+ 中文类型和可信业务日期；没有可信业务日期时显示「日期未记录」。
   - 不显示 `relative_path`；普通阅读界面不展示内部路径。
5. **有效性提示**（必要时）：例如"引用保存的是回答当时的页面版本；该页面已更新，当前显示的是新版本，不能替代原回答依据。"
6. **正文**：`<MarkdownText>` 渲染，正文列 `max-width: 72ch`，系统无衬线 15px/1.75。代码块按语言做语法高亮（关键字 / 字符串 / 数字 / 类型四色，见 `--code-*`），行内代码用强调色；正文开头若是一级标题且与页面标题相同，渲染时去掉，避免标题出现两次。**页面详情只读**：不提供编辑正文、插入链接或新增内容的入口；内容由外部来源写入，改完回来源文件，应用只负责发现变化、确认当前版本与索引。正文区不出现任何 `select` / `input` / `textarea`。
7. **页面操作抽屉**（仅已确认页）：只放「移动到其他项目」——显示当前归属与后果，确认后写入；它只改归属，不动正文。
8. **确认面板**：仅待确认页出现，说明"只对这一版生效；文件改动后需要重新确认"，并提供「确认当前版本」。这里没有编辑器。
9. **翻页**：正文尾部提供「上一篇 / 下一篇」，取当前页所在文件夹的直接页面、按 `relative_path` 排序；换页回到正文顶部。这是窗口不足以显示左目录时的连续阅读入口。

### 三态
- 加载："正在读取页面…"；目录区单独显示"正在读取目录…"，不得写成空目录。
- 空：页面不存在 → 错误态处理（见下）。
- 错误：路径不存在/版本冲突 → 白话说明 + 「重新读取当前版本」；版本冲突必须给出"当前显示的是新版本，不能替代原依据"的提示。

### 诊断信息
- 普通阅读不显示完整路径、`content_sha256` 或内部 ID；只有用户主动导出的诊断材料可包含这些值。日期不使用文件修改时间推测。

### 不做什么
- 不用 `<pre>` 显示正文。
- 不用等宽字体显示正文。
- 不在页头显示文件路径。
- 不在页面详情里编辑正文、插入链接或新增内容；这些属于外部来源，应用不处理内容冲突。
- 不把「移动到项目」放在正文尾部当阅读的下一步。

### 验收点
- 正文渲染 Markdown，可见文本无 `**` / `[[` / `##`（守卫 ⑥）。
- 已确认页与待确认页的正文区都没有 `textarea` / `input`，也没有「插入链接」这类新增入口。
- 状态徽章与主操作一一对应；历史版本没有"确认"按钮。
- 普通阅读文案、hover、标题和详情不显示路径；路径只可随用户主动诊断导出。

## 7. 知识问答（`components/AskView.tsx`）

### 职责
问一句，拿到带出处的答案。这一页只做两件事：**搜索**和**看结果**。

### 主操作
提问框的「开始检索」（唯一 `.button.primary`）。

### 结构（提问框在第一屏第一块）

1. **页头**：`知识问答` + 右侧「新建对话」。
2. **提问区**：多行输入（有可见的淡色输入面）+ 第二行三个选项（资料范围 / 回答方式 / 本次使用角色）+ 发送前的真实 provider / 本地索引就绪提示 + 右下「开始检索」。缺密钥、模型或有效索引时说明原因并给设置/审批入口；当前问题不发送且保留在输入框，就绪状态未核实时主按钮禁用。没有输入内容时按钮禁用，但仍是主色（淡化），不是灰色次要按钮。
3. **本次回答 / 发送预览**：提问区之后立即显示待确认的真实发送范围预览（若存在），再显示当前回答；答案以流式 Markdown 呈现，状态用 `role="status"` 固定文案，有「停止」。取消/中断不写进红色横幅。运行中的答案始终在最近历史和既有对话轮次之前，避免滚动查找当前输出。
4. **最近的问答**（没有对话时就是页面主体）：当前回答之后是列表，一行一段：标题 + 时间 · 问题数 · 状态；右侧「删除」（需确认）。点击时该行立刻显示「正在打开这段对话…」（整行禁用、连点只发一次请求）；**打开过的对话在内存里留一份（最多 20 段）**，再次点开先铺上次内容、不显示 loading，后台静默取最新版本再替换。空态是"还没有问答历史。问第一个问题吧。"。有更多时给「加载更早历史」。**不再是一个折叠块，也不在页面底部。**
5. **对话记录**：提问后列表让位给对话；每条 = 你的问题 + 回答 + 出处。追问进行时，本次回答先于既有轮次，完成后答案随轮次保留。对话上方**左上角**给「← 返回最近的问答」（返回是导航动作，跟浏览器返回同侧），不在标题右侧放返回。
6. **出处**：跟在每条答案内部（序号 + 页面名 + 区块标题 + 摘要），点开在应用内打开页面。失效引用要标注"版本已更新，不能作为当前依据"。
7. **中断提示**：一行灰色小字「上次连接中断，已保留收到的部分内容（不会自动重试）」+「继续提问」；只有一个字都没收到时才用红色。

### 不在这一页
- **本机索引**、**问答角色**、**问答记忆** → 「设置 → 知识问答」（`components/AskPreferences.tsx`）。索引的建立与更新仍然只在审批页发起。
- 页面底部不再有索引/角色/记忆三块，也不再有折叠的「问答偏好」。

### 三态
- 空：历史为空 → "还没有问答历史。问第一个问题吧。"；没有引用 → "没有找到可引用的依据"（仅正常完成且无引用时）。
- 错误：模型未配置/未启用/缺密钥 → 提问区提前说明并提供「去设置」；发问后才发现的错误与恢复入口位于有间距的容器中，保留输入的问题。计划预览或 `/settings` 失败说明本次问题尚未发送。
- 本机索引缺失或向量模型不匹配：保留输入的问题，说明尚未预留/发送模型请求，并提供「前往审批建立或更新索引」；同 fingerprint 的部分内容陈旧仍允许查询，由当前内容资格规则逐页过滤。
- 中断：保留已收到的部分内容，说明不会自动重发，给「继续提问」。

### 折叠项（L2）
- 「本次详情」：服务与模型名、请求次数与上限、思考预算、耗时。
- 内部页面 ID、版本 hash、request_id、`source_message_id` 只进用户主动导出的诊断材料。

### 不做什么
- 不在提问框和结果之间插索引状态、角色设置或记忆管理。
- 不把历史做成页面底部的折叠块；它在当前回答之后、对话记录之前。
- 不把 64 位 `fingerprint` 写进可见文本；不在流式容器上挂 `aria-live`；不把答案整段用等宽字体。

### 验收点
- 提问框是第一块（守卫 ⑧ 的变体），历史列表在它下方。
- 答案渲染 Markdown 且流式中间态无未闭合标记（守卫 ⑥）。
- 列表/刷新不调用模型（守卫 ⑨）。
- 索引指纹不出现在可见文本（守卫 ①）。

## 8. 设置（`components/SettingsView.tsx`）

### 职责
连接工作库、模型、飞书；填一次就够。

### 主操作
每张卡自己的连接动作（同一屏可以有多张卡的主操作，但**每张卡内只有一个** `.button.primary`）。

### 结构

1. **页头**：`设置` + 右侧「打开连接向导」。下方只留一行模式状态（`试用模式（不联网）` / `正式连接（会联网）`）与最近读取时间，不再放页面说明。
2. **主区三张卡，每张独占一行**（`grid-template-columns: minmax(0,1fr)`）：
   - **工作库**：标题 + 状态徽章 + 「当前工作库」一行 + 「切换工作库」。标题下不放说明段。
   - **AI 模型**：三行能力名 + 状态；三项禁用原因相同时合并为一行脚注；「如何启用真实模型」默认折叠。模型名、账户与密钥收在高级配置。卡片唯一主操作「配置 AI 模型与密钥」。
   - **飞书**：四行能力名 + 状态；读取类能力共用一行脚注；已授权时只保留一行「不表示身份已核实，也不能写回飞书任务」。主操作「连接飞书」复制给 Codex / WorkBuddy 的自包含提示词；技术 App ID、端点、callback、账号标识和手动兼容配置收进高级区。
3. **知识问答卡**（`.settings-ask-card`，问答页不再管这些）：三段——**本机索引**（可索引 / 已索引 / 待更新 + 「前往审批处理索引」，建立与更新仍只在审批发起）、**问答角色**（使用角色 / 名称 / 预算 / 表达偏好 + 保存、删除）、**问答记忆**（待确认候选可确认，已确认可改可删；删除需确认）。只读本机，不联网。
4. AI 配置入口进入高级与自定义；设置页的飞书主入口复制助手接入提示词。工作库卡的切换入口回到共享流程第 1 步。
5. **「高级与自定义」**（默认折叠，展开不改变数据）：DeepSeek 账户、回调地址、DeepSeek 检查额度、预算、模型参数（只读）、诊断与日志、「设备与工作库标识」。分区标题按内容分组，别堆成一个长列表。
6. **危险区**（放在「高级与自定义」底部）：按密钥项删除本机密钥。**每项都有确认弹层**，写清只删除所选密钥且工作库文件不会删除；该钥匙串密钥删除后无法从本机恢复。断开飞书/移除工作库仅在有对应真实动作后展示。

### 三态
- 加载：显示明确的本机设置读取状态，不能伪装成空态或已连接。
- 错误：设置读取失败时各张卡各自显示"暂时无法读取"与重新读取入口；成功状态不得由单一模型检查或失败的读取推断。
- 空：未配置就是未配置，徽章说清下一步（不显示空白）。

### 折叠项（L2）
- 本地模型准备状态、DeepSeek 账户、callback、预算、模型参数、读取时间。
- L3：`embedding_fingerprint`、完整工作库路径、设备标识，只在诊断导出里。

### 不做什么
- 不把自动化/设备/诊断放在主区（现在已收进折叠区，保持）。
- 不在主区让用户手填 Base URL / callback / App ID。
- 不显示"请勿在聊天中发送密钥"这类面向开发团队的文案（该说的在向导字段旁用一句白话说明即可）。
- 不在深色下用写死的浅色背景（守卫 ⑦）。

### 验收点
- 主区恰好 3 张纵向卡（工作库 / AI 模型 / 飞书），每张只有一个主要操作（守卫 ⑧）。高级区默认折叠；刷新、展开、保存不调用 provider。危险操作确认前不写入，确认后仅删除所选密钥。
- 深色下输入框、通知条、徽章全部可读（守卫 ⑦）。
- 每张卡独立降级，单卡失败不影响其他卡。
- 危险动作都有确认弹层（守卫 ⑤）。

## 9. 共享组件规格

| 组件 | 规格 |
|---|---|
| `<MarkdownText>` | GUIDE §7.2。唯一允许渲染用户内容的入口；默认不渲染原始 HTML；链接外开 + `rel="noreferrer noopener"`；内部页面链接走 `onOpenPage` |
| `<StreamingMarkdown>` | GUIDE §7.3。`stabilize()` 容错 + 尾部光标 + 结束时以完整 buffer 收敛；不挂 `aria-live` |
| `<Toast>` / `useToast()` | GUIDE §5.2。右下角固定列，最多 3 条，成功 3.5s，失败常驻可手关；文案不含 ID/路径 |
| `<ConfirmDialog>` | `role="dialog"` + `aria-modal="true"` + 焦点陷阱 + Esc + 焦点归还；标题写动作、正文写影响与可恢复性、主按钮 `.button.danger` |
| `<EmptyState>` | 图标/标记 + 一句话原因 + 一个可点入口；中性语气 |
| `<LoadingBlock>` | 骨架或"正在读取…"；**不得**与 `<EmptyState>` 混用 |
| `<StatusBadge>` | 只用 `--ok/--warn/--danger/--quiet` 四类语义；文案经纯函数映射，未知值给"需要处理"而不是空白 |
| `<PageHeader>` | `h1` + 右侧动作区（≤1 个 primary / 日期）；不提供 description，标题下不加副标题 |
| `<Icon>` | 一律 `lucide-react`；导航 18px、行内 14px、动作 14–15px、折叠 15–16px，描边 1.75；禁止 CSS/Unicode 图标 |
| `<Details>`（L2 折叠） | 统一标题「本次详情」或「技术信息」；`<summary>` 可键盘操作，展开不改变数据 |
| 危险动作按钮 | `.button.danger`，只出现在确认弹层与列表行内次要位置；≥36px（细指针）/44px（粗指针） |

## 11. 2026-10-28 实现收敛（不改变区块顺序）

用户确认日常自用阶段以「少废话、有主次、能收纳」为准。以下调整只改变同一区块内的呈现密度，**五栏导航与各页区块顺序不变**；决策记录见 [ADR 0013](../decisions/0013-daily-ui-and-hot-reload.md)。

| 页面 | 调整 |
|---|---|
| 全局 | 去掉页面级 eyebrow 与副标题；每页一个标题，标题即功能。样式按页拆分，统一 `.panel` / `.section-head` / `.pill` / `.disclosure` / `.empty-row`。 |
| 今日 | 会议与待办合并为一张「今天的安排」卡，每个小区块自带标题与唯一的次级刷新入口；右侧仍是记录、导入与最近材料。 |
| 审批 | 五组固定顺序保留。收起态只显示编号、标题与数量；组说明移进展开内容。筛选改为分段按钮。 |
| 设置 | 三张纵向卡保留。AI / 飞书能力清单压缩为名称 + 状态；相同的禁用原因合并为一条脚注；下一步动作收进折叠区。 |
| 知识问答 | 搜索 + 结果页：提问区、下方直接的「最近的问答」列表、回答与出处；索引/角色/记忆在设置里。 |
| 项目 | 页头与列表共用左边界；全部档案为空时只显示一行引导；时间线摘要只取第一行纯文本，不渲染整段正文。 |
| 阅读 | 正文优先；「整理页面」单独成组，置于正文之后。 |

验收仍以既有守卫为准：字号只走 token（≥12px）、颜色只走 token、内部 ID/路径/hash 不进入普通界面、加载/空/错误三态分离、危险动作确认不减少。
