# SummitEverything 产品规格

状态：用户确认的 v1 规格。日期：2026-10-09。

## 用户、问题与成功

首先服务罗艺峰本人，未来可以交给同事独立使用。原始工作材料已存在，但缺少与本人业务习惯一致的输入、整理、审核和知识积累流程；prompt 驱动的通用 agent 不能替代这些固定流程。

产品价值是可信、可复用、可迁移的工作知识。一个应用完成整理和检索，普通 Markdown 是核心资产，可以与 Obsidian 等工具一起使用。

成功包括：真实材料能进入正确权威页；批准与未决事项表达清晰；查询能追溯依据；外部编辑不会继续使用过期批准；单台 Mac 可以完整工作，再验证 Studio / Air 轮流使用。

## 已确认的 v1 能力

### 组织知识

- 用户自由增删改线，管理项目；不预设旧八个项目或 workstream 枚举。
- 线 → 项目 → 页面；项目可以是长期主题，不强制有结束日期或固定子项目层。
- 页面有一个主项目；其他项目链接同一页，重要事实有一个权威落点。
- 粗分类为对象档案、案例、主题知识、业务决策、工作日志、工作思考；项目总览是项目的入口页。分类不规定正文区块。
- 项目总览维护范围、目标、总体判断和进展。酒店价格、期次结算等具体事实引用权威页。
- 内容确认、业务进展、知识效力分别表达。项目归档不自动使知识失效；回答区分当前与历史依据。

### 输入、整理与确认

- 手动粘贴文字、导入 TXT / Markdown、批量选择文件或文件夹。
- 已授权连接后的飞书日历可在今日页和 MCP 中直接刷新读取；范围由用户选择的时间段、身份与已授予 scope 限定，服务端实行有界请求且失败不自动重试。飞书待办和材料列表仍需本次计划预览与确认；妙记等材料先人工选择，再获取内容并发起整理。
- 列表和随手保存不调用模型。随手记录先留在可见的待整理区，之后选择单条或一批处理。
- 今日页在宽屏同时呈现会议/任务与随手记录/材料导入；会议默认 3 条、任务默认 5 条，可展开并继续分页。保存和导入回执按接口实际返回的材料 ID 接续；已有整理任务或稿件时继续现有阶段，不重复发起作业。
- 模型忠实重组原文，去重复、改善表达，保留事实 / 想法 / 建议 / 未决事项的区别；默认不增添分析结论。
- 一份输入可产生多个完整新增 / 更新稿。每稿独立确认，允许只接受部分；默认更新现有权威页而非积累多份重复纪要。
- 普通入库保留原件与衍生稿，明确标识原件且永不检索。不生成独立正式会议纪要；有价值内容落为对象、案例、主题或决策等。
- 重要冲突展示各自依据，用户选择采用哪项或明确未决后确认。待审稿不覆盖已确认页。
- 审阅默认显示完整新稿，并能看改动和来源。任务操作、项目进度变化与知识批准分别确认。
- 直接写工作日志 / 思考有独立入口，可以不绑定项目；明确保存并确认可形成批准，不必绕一遍 AI 整理。AI 辅助是显式动作。
- 外部 Markdown 编辑允许；发生语义版本变化时进入待确认，停用旧索引内容，重新确认后增量索引。

### 检索与问答

- 查事实、跨材料归纳比较、提出工作方案都在 v1 内。
- 回答必须区分来源支持的陈述和 AI 推断 / 建议；证据不足明确说明，不补造业务事实。
- 引用可打开页面与对应位置，并绑定内容版本。过期引用显示内容已更新，不能悄悄把新页面当成原答案依据。
- AI 答案不自动变成正式知识；后续显式保存也要进入用户确认流程。
- 保留本地聊天历史与角色管理。角色主要用于问答，不改变整理忠实性、批准规则和工具权限。
- 可由本机 Agent 通过受限 MCP 工具读取符合资格的已确认知识、导入文本和提交/编辑待审稿；MCP 输出和草稿都不能批准正式知识，最终确认仍由应用用户独立完成。当前不开放 Agent 任务执行或确认工具。
- 长期记忆只从用户明确表达形成候选，经用户接受 / 编辑后生效；原件里的话、模型推断和模型回答不能自动成为用户事实。

### 日常与连续使用

- 飞书是正式任务唯一执行账本；应用负责展示、创建、编辑和完成，不维护第二套正式本地任务。
- 未确认任务建议留在待处理区。外部结果未知时核实，不能重新 POST 冒险重复建任务。

### 飞书连接方式（2026-10-10 用户决议）

- 今日页与设置主区的「连接飞书」入口复制自包含的 Codex / WorkBuddy 接入提示词，不启动手动配置向导、不从该按钮发起 OAuth 或外部请求。提示词不依赖助手 cwd、源码仓库或文档；先用已连接 MCP、宿主项目配置和实际运行进程等有限证据核对网页 origin 对应的实例。只有确认源码根目录属于该实例后，才可将源码文档作为可选补充；没有源码/只有安装应用时按提示词内完整安全步骤继续。不能默认网页 origin 等同 API origin，也不得猜替端口；已证实的同源 API 或受支持本机代理可以使用。发现并复用现有 MCP、飞书授权与安全配置；只有能力确实缺失时才报告最小动作。提示词只含当前网页 origin，不含查询串、片段或凭据。剪贴板拒绝时在原处提供可选择的提示词及重试。
- 复制提示词不代表已连接飞书，也不授权真实任务写入、正式知识确认、付费模型调用或代替用户确认/绕过一次性计划。客户端/MCP 接通、飞书外部授权、SummitEverything 实际读取飞书数据分别验证；密钥不得通过聊天传递。手动配置保留在高级 / 兼容入口。

- 应用身份优先：能用应用（tenant）身份完成的读取就用应用身份，不要求用户登录。
- 具体功能确需用户身份时（例如妙记搜索、任务列表按官方要求只接受 `user_access_token`），首次授权一次，之后自动续期；续期失效时明确提示重新授权。
- 不得把 OAuth 作为所有飞书功能的统一前置条件；也不得假定 App ID / secret 能访问全部个人资源。
- 按具体 endpoint 记录所需身份、scope、资源范围与原因；遇到权限错误时只禁用受影响能力并给出可读原因，不自动切换身份扩大访问范围。
- 用户是自建应用管理员，可按需开通 scope；scope 可开通不等于接口语义已确认。
- 知识和未完成整理 / 审核流程随工作库迁移。诊断日志、聊天历史、角色、记忆、向量索引、缓存和凭据各机本地保存。
- 2026-10-30 用户明确真实交付规则（取代默认 Fake 决议）：正常启动和交付界面只使用 DeepSeek 进行整理/问答、本地 BGE 进行向量化与排序；不能选择或自动降级到 Fake/Mock/测试 provider。首次配置只引导准备真实服务；缺密钥、钥匙串、本地模型或旧索引时明确显示未就绪与下一步。Fake/Mock 仅允许通过自动化测试显式注入隔离依赖，不能成为正常启动配置或产品入口。已有 Fake 配置迁移为 real + DeepSeek/local 的准备状态，不得报告服务或索引 ready。密钥留在本机钥匙串，不打包或通过聊天传递。
- 用户于 2026-10-14 确认首次配置按工作库 / AI 模型 / 飞书分卡片；该日确认需录入 DeepSeek、DashScope、Feishu AppSecret 的旧决定，已由 2026-10-29 的本地检索决议更新：现在只有 DeepSeek 与 Feishu AppSecret 属于模型 / 飞书密钥；索引和排序不使用云端服务或密钥。DeepSeek 合成检查必须由用户显式发起并确认，不做保存后自动联网。密钥不打入安装包或仓库。详见 [ADR 0031](../decisions/0031-local-retrieval-deepseek.md)。
- 用户于 2026-10-15 明确：工作库选择是同一首次配置流程的第 1 步，由应用级流程宿主在打开工作库后原地进入模型与密钥步骤；无工作库时关闭回欢迎连接页，选库后关闭回来源业务页。其它首次配置入口仍复用该流程；未完成且仍打开的步骤按真实本机 profile + workspace 身份保存，应用页重载恢复原步骤；用户明确关闭后不自动弹出。2026-10-29 用户补充决议（[ADR 0029](../decisions/0029-feishu-agent-setup-entry.md)）：今日和设置主区的飞书连接入口复制助手接入提示词，手动配置保留高级 / 兼容区。密钥仍不持久化到网页存储，完成状态与服务端能力状态分开判断。
- 这是目标使用体验，不表示当前 Real 配置、真实账户的 endpoint/scope、OAuth、token vault 或 OS Keychain 生命周期已经通过。当前实现字段审计、账户所需配置与未测边界见 [M42 readiness](../handoff/M42-PACKAGE-A-READINESS.md)；真实连接继续按本文件的授权要求单独执行。
- 每台电脑独立运行。首版 DMG 内部 WebUI，使用者安装一个应用、双击使用。
- 先完整单机验收，再连续五个实际工作日试用，之后双机。双机允许同时读取，轮流写入；用户确认 OneDrive 已同步后换写端。
- 批准变更自动增量索引；首次索引、模型切换和完整重建需显式查看范围并确认。检索索引由用户本机的已准备模型构建，不创建付费服务计划；对话生成模型调用仍需一次性预览与确认。

### 本地检索与生成模型（2026-10-29 用户决议）

- 产品采用本地向量化、本地混合检索与本地排序；DeepSeek 只负责整理和生成式问答。搜索和本机索引在没有 DeepSeek key 时可用。
- 首次下载由用户在设置明确启动，文件按固定公开 revision 与 SHA-256 校验；缺失或损坏时明确提示准备，不隐式下载、不退回云端。源稿、正式页面及索引文本不发给云端 embedding / rerank 服务。
- 本地索引计划保持页面范围、版本和显式确认；预览与执行不预留或计收外部模型请求。
- 旧 DashScope 值可兼容读取，但不能运行；迁移到本地检索需用户显式切换，已有密钥保留，不由迁移删除。
- 审批按来源、稿件、正式内容、索引、外部动作分成五个可折叠组；有待处理项的组展开，空组可展开查阅。稿件冲突选择仅在用户确认稿件时生效，界面不得把未持久化选择显示为已保存。

## 初始化与真实样板

首个真实样板是「行政&后勤 / 场地与酒店」，来自四份桌面 Markdown。其业务事实尚未整组批准，不能把录音纪要、先前待审 frontmatter 或先前逐页修订当最终批准。

用户最新决议：通用代码可先用隔离模拟材料开发。真实样板在合适阶段由专门 grillme 确认，再初始化；不阻塞通用编码。

本样板初始化是一次性准备，不是产品日常功能。样板只把最终确认内容写入新库，不复制其原件；原桌面文件保留。普通入库仍保留原件。

## 暂缓及边界

- v1 只做工作知识库；个人库、团队共享编辑和多机同时写入暂缓。
- 音频由外部工具转成文字；PDF / Word / 图片 / OCR 不在首版导入范围。
- 不把初始化专用 grillme 做成日常必经的交互功能。
- 不支持工作库 Git 同步、冲突、自动提交或 Git 撤销。
- 不同时交付 Docker 版本，不部署常开共享服务器，不公开发布旧应用的替代更新。

## 决议与工程默认

上面的能力与边界来自用户明确选择；录音纪要仅是讨论材料。

工程默认：Python / FastAPI、React / TypeScript、SQLite 本机状态库、嵌入式 LanceDB 本机检索库、薄 macOS 壳；SQLite 保存业务状态和索引代指针，LanceDB 保存可重建的向量及全文索引。模型适配与实际参数见架构文档。这些默认不授权改变产品行为。

最后三项交接决议：①隔离模拟材料先编码；②验收者可增补测试，产品修复由执行者负责；③文档覆盖完整 v1。框架代码只锁定共同契约，不能把基础测试数量当完整产品完成证据。
