## 1. 十条不可违背的设计原则

1. **一个入口一个职责。** 导航项 = 一个日常目的地，不是一种能力。加功能先问「它属于哪个已有目的地」，答不出来就不加导航项（SWB 从 7 个页签收敛到 4 个，删掉独立的「第二大脑」「指南」「决策」页签）。
2. **每屏只有一个主操作，且它在折叠线以上。** 每页恰好一个 `.button.primary`；用户不需要滚动才能知道"下一步点哪"。
3. **主界面说白话，工程细节分级下沉。** 用户永远先看到"发生了什么 + 下一步点什么"；ID / hash / 路径 / 原始 JSON / 请求次数只在折叠区或诊断导出里（§9）。
4. **中文优先。** 可见文本用中文；英文技术词进括号或 `title`；内部标记（`unresolved`、`processing`、`crashLoop`）绝不出现在界面上。
5. **内容渲染成内容。** Markdown 正文与模型答案按排版渲染并支持流式；源码标记（`**`、`[[`、`##`、`|`）不得被用户看到（§7）。
6. **不确定就说不确定，失败就说下一步。** 结果未知写「结果未知」并给出核对入口，绝不写成成功；每个错误文案都带"怎么办"。
7. **危险动作要确认，付费动作要范围预览。** 删除 / 断开 / 覆盖必须弹确认；调用模型或外部服务保留 SE 现有的一次性范围预览 + 显式确认（这是 SE 的强项）。
8. **加载、空、错误是三件事。** 读取中绝不显示"还没有…"；空态说明为什么空、下一步做什么；错误不得占用成功/中性的样式。
9. **所有颜色、间距、字号、圆角都走 token。** 组件里不出现裸 hex、不出现 9–11px 的字号、深色模式是一等公民（§6）。
10. **界面不撒谎。** 静态绿点、永远"已保存"、假头像、没有入口的能力、承诺不存在的恢复——都算缺陷。

## 4. 语言与措辞口径

### 4.1 每页必须有一句"想做什么就点哪里"

页头（`h1` 下方）一句 `.lede`，用第二人称、动词开头，说清这一页能干什么。示例（照抄照改，不要写成功能清单）：

- 今日：「今天要开的会、要做的事都在这里。随手想到的先记一句，之后再整理。」
- 审批：「需要你点一下才算数的都在这里——先整理来源，再复核稿件，最后确认正式内容。」
- 项目：「这里的每一条线是一个业务方向。点进去看它现在到哪一步、下一步做什么。」
- 知识问答：「问一句，答案会带上出处。点出处能打开原文。」
- 设置：「连接工作库、模型和飞书。填一次就够，之后不用再管。」

### 4.2 白话替换表（强制）

| 不要写 | 要写 |
|---|---|
| processing / reviewing / pending（裸状态码） | 整理中 / 待审核 / 待整理 |
| 独立确认此动作 / 本次范围确认 | 确认并整理 / 只发送这一次 |
| unknown / UNVERIFIED | 结果未知，请先核对 / 还没验证过 |
| sha256 / fingerprint / operation_id | 「本次详情」折叠区，或不出现在界面 |
| Fake · 离线（默认）/ Real · 显式启用 | 试用模式（不联网）/ 正式连接（会联网） |
| Embedding Base URL / Rerank API Base URL | 向量化服务地址（embedding）/ 精排服务地址（rerank） |
| 注册 callback URI | 飞书回调地址（已内置，一般不用改） |
| 最多 3 次 HTTP 请求：embedding、rerank、回答各一次 | 这次会问一次模型（约 3 个请求）；费用估算见「本次详情」 |
| embedding_fingerprint | 不用出现在句子中；需要排查时进诊断导出 |
| relative_path | 页面的显示名；路径只在「技术信息」里 |
| 该操作缺少可独立核实写入结果的方式 | 写没写成功还没法确认，请去飞书核对一下 |

### 4.3 中文优先（机器守卫 ②）

- 主显中文名（项目 / 主线 / 页面 / 记录类型）；英文 ID 只进 `title`（hover）或折叠区；**唯一例外是"引用来源"**，它保留完整路径（SWB 的用户裁决原话：「主显中文名，英文 ID 放次要位置（小字 / hover），只有『引用来源』保留完整路径」）。
- 没有中文名时退回 ID，但要在 UI 上标注它是标识符（例如 `frontend-guide（标识）`）。
- 错误文案必须中文打头，英文技术词只能进括号。
- 状态码一律经纯函数映射为中文句子后再上界面（沿用 `web/src/api/client.ts` 的 `indexUpdateMessage` 与 `settingsBadges.ts` 的做法）。

### 4.4 每个高风险文案都要声明"不会发生什么"

不可逆或外部动作，除了说"会做什么"，必须说"不会做什么"：

- 整理：「只生成待审核稿，不会直接写入正式知识。」
- 正式内容确认：「只对当前这一版生效；文件改动后需要重新确认。不会创建飞书任务。」
- 删除：「删除后无法恢复，原件不会进回收站。」（删除项目/主线时补一句"页面不会从磁盘删除"如果属实）
- 导入：「只保存原件到待整理区，不会调用模型。」
- 本地写入：「写入的是本机文件；同步由 OneDrive 客户端负责，本地回执不等于已同步。」

### 4.5 状态词短、解释另起一行

密集区域（列表行、徽章、顶栏）只用短状态词（2–6 字）；解释、下一步、恢复动作放在其下一行或 `title`。不要把一个长句塞进徽章。

### 4.6 空态分三种，不要一句话打天下

项目列表要区分：**搜索无命中**（"没有匹配「xx」的项目，清空搜索看看"）、**筛选到某类为空**（"这个状态下还没有项目"）、**真的没有**（"还没有项目。先建一条主线，再建项目。"）。其他列表同理。

## 5. 组件与交互规则

### 5.1 按钮层级

| 类 | 用途 | 约束 |
|---|---|---|
| `.button.primary` | 当前屏唯一主操作 | **每屏最多 1 个**；busy 时文案改成进行时（"正在保存…"）并 `disabled` |
| `.button.secondary` | 次要并列动作 | 不改变数据或可反悔的动作 |
| `.button.danger` | 破坏性动作 | 只出现在确认弹层与列表行内次要位置；需新增 `--danger*` token |
| `.text-button` | 行内链接式动作（改名、查看） | **不得**用于删除/断开；最小点击高度 36px（细指针）/44px（粗指针） |
| `button[aria-label]` / 图标按钮 | 图标动作 | 必须有 `aria-label` + `title`；≥36px（细）/≥44px（粗） |

### 5.2 反馈（机器守卫 ⑤）

- **toast**：右下角固定列，最多同时 3 条；成功（绿）/ 失败（红）/ 中性（灰）三色；成功 3.5s 自动消失，失败不自动消失（可手关）。文案 = 做了什么 + 落在哪 + 下一步，**不夹 ID/路径**（SWB 的教训：回执文案从打印 vault 路径改成了"工作日志已保存，可在最近操作结果中查看记录"）。
- **busy**：按钮改文案（不只变灰）；同一请求有单飞（in-flight）守卫，重复点击不得发出第二个请求。
- **删除/断开/覆盖确认**：弹层必须写清三件事——会删什么、能不能恢复、恢复不了就直说。确认按钮用 `.button.danger`。取消按钮永远在左、默认焦点在取消上。
- **付费/外部动作**：保留 SE 现有的一次性范围预览 + 独立确认，但**降低术语负担**：主位一句白话（"这次会调用整理模型一次，只生成待审核稿"），请求次数 / token 上限 / 价格公式 / 操作编号全部进「本次详情」折叠区。取消路径必须证明"什么都没发送"（SE 已有此行为，保留）。
- **结果未知**：写「结果未知，请先核对」并提供核对按钮；禁止自动重发。

### 5.3 三态（机器守卫 ④）

| 状态 | 要求 |
|---|---|
| 加载中 | 骨架或"正在读取…"；**绝不允许**出现空态文案。文件级/卡片级读取失败只降级该卡片，保留上一次成功值并标注读取时间（沿用 `SettingsView.tsx:234` 与 SWB `settings/render.ts` 的做法） |
| 空 | 一句"为什么空" + 一个"下一步"入口（可点击）。中性语气，不指责用户 |
| 错误 | 就地显示、可关闭、可重试；不复用成功/中性样式；**cancel/信息不得走红色横幅**（现在 `TodayView.tsx:237`、`AskView.tsx:458,465` 把"已取消"涂成红色错误） |

### 5.4 表单与向导

- 字段级错误贴在字段下；必填缺失时**禁用主按钮并用 `title` 说明缺什么**，而不是提交后弹一条通知（现在 `FirstUseWizard.tsx:122-124,175-177` 用通知代替校验）。
- 向导步骤状态按真实本机 profile + workspace 身份保存（仅非秘密：当前步、完成与显式打开状态）；仍打开时重载自动续接，显式关闭不自动弹但可从设置手动续接，完成后不再自动打扰。
- 破坏性输入（删除确认）不用纯文本匹配，用明确的确认弹层。

### 5.5 弹层与键盘

- 弹层：`role="dialog"` + `aria-modal="true"`（现在写的是 `false`）+ 焦点陷阱 + Esc 关闭 + 关闭后焦点回到触发按钮 + 打开时焦点落在第一个可操作元素（或标题）。
- 全局：skip link（"跳到主内容"）；侧栏当前项 `aria-current="page"`；表格/长内容容器可横向滚动而不是撑破页面。
- `aria-live`：**不得**挂在流式增长的容器上（现在 `AskView.tsx:576` 就是）。改为一个固定的 `role="status"` 文案，开始时播报"正在回答…"，结束时播报"回答完成"；答案本体 `aria-live="off"`。
- 保留 `prefers-reduced-motion` 处理。

### 5.6 顶栏与侧栏的真实性（机器守卫 ①）

- 「本机已保存」必须绑定真实保存状态（空闲/保存中/保存失败），否则删掉。
- 「仅本机运行」保留，但必须是真实描述而不是装饰性绿点。
- 删掉硬编码头像「罗」；工作库切换入口不要用 `⌄` 暗示一个不存在的下拉菜单——要么实现菜单，要么去掉箭头并改文案。
- 深色模式提供手动选择：跟随系统 / 浅色 / 深色，存 `localStorage`，并在 `index.html` 首屏前应用以避免闪烁。

## 6. 样式系统

### 6.1 tokens（唯一真源，放 `web/src/theme-tokens.css`）

### 6.2 深色模式（机器守卫 ⑦）

- 主题由 `<html data-theme="light|dark">` 驱动，**不是**只靠 `@media (prefers-color-scheme)`；`index.html` 里加一段首屏前脚本读取 `localStorage` 的偏好（`sx:theme-preference`，取值 `system|light|dark`），避免闪白。
- `:root[data-theme="dark"]` 覆盖**全部**颜色 tokens；`system` 由脚本解析为 light/dark 后写入 `data-theme`。
- 禁止"在深色下仍然写死浅色"的规则。当前必须修掉的四处：
  - `App.css:124` `.settings-field input, select { color: var(--ink); background: #fff }` → 深色下白底 + 近白字（不可读）。改为 `background: var(--surface)`。
  - `App.css:126` `.settings-notice { background: #f0f5f0 }` → 改为 `var(--green-wash)`。
  - `App.css:167,185,187` 的 `#fbf4e8` / `#f0f5f0` / `#9cc3a4` / `#d8b878` / `#d9967b` → 走 `--warn-*` / `--green-*` / `--danger-*`。
  - `App.css:23,24,25,32` 侧栏与头像的硬编码色 → 走 `--sidebar-*`。
- 对比度机器断言（照 SWB `web/scripts/test-theme.mjs` 的做法，两套 tokens 各算一遍 WCAG 比值，并打印结果）：`ink/paper`、`muted/paper`、`ink/surface`、`muted/surface`、`on-accent/accent`、`accent/accent-wash`、`green/green-wash`、`danger/danger-wash`、`warn/warn-wash` ≥ **4.5:1**；`control-border/surface` ≥ **3:1**。

## 7. 排版、阅读与流式 Markdown

### 7.1 字号尺度

| token | 用途 | 行高 |
|---|---|---|
| `--text-display` 31px | 首次配置的大标题 | 1.3 |
| `--text-page` 22px | 页面 `h1` | 1.3 |
| `--text-section` 16px | 区块标题 `h2` | 1.4 |
| `--text-body` 15px | 正文、答案、页头 `.lede` | 1.75（正文）/ 1.6（UI） |
| `--text-list` 14px | 列表行主文本、按钮 | 1.5 |
| `--text-small` 13px | 次要说明、hint | 1.6 |
| `--text-caption` 12px | 徽章、计数、时间戳（下限） | 1.4 |

- **等宽只用于**代码、文件路径、"引用来源"、ID/hash（且只在折叠区或诊断）。正文与模型答案一律系统无衬线。
- 正文列宽 `max-width: var(--measure-read)`（72ch），段落 `overflow-wrap: anywhere`。

### 7.2 Markdown 渲染（机器守卫 ⑥）

- 引入 `react-markdown` + `remark-gfm`（用户已确认）。**不启用 `rehype-raw`**：不渲染原始 HTML（SE 必须保持防 XSS）。
- 统一组件 `<MarkdownText source={...} />`，所有需要显示正文的位置都用它：页面阅读页、审核稿正文与差异、问答答案、项目概览、日志/思考预览、导入预览。
- 必须支持：标题、有序/无序/嵌套列表、任务清单（`☐`/`☑`）、表格、引用、行内代码与代码块、粗斜体、链接、`[[目标|标签]]`（只显示标签，目标进 `title`）。
- **禁止**可见文本出现 `**`、`__`、`[[`、`]]`、行首 `##`、表格分隔行 `|---|`。
- 链接一律 `target="_blank" rel="noreferrer noopener"`；内部页面链接走应用内打开（SE 已有 `openPage`），不新开标签页。

### 7.3 流式渲染口径（用户确认：边流边渲染 + 容错）

同一个 `<MarkdownText>` 加一层"流式稳定化"，不要让半截语法闪现在用户眼前：

1. 累积 SSE 文本到 `buffer`。
2. `stabilize(buffer) -> string` 返回**可安全渲染的前缀**：
   - 未闭合的围栏代码块：整段按代码块渲染（临时补围栏）或按纯文本渲染，闭合后立即转为代码块。
   - 末尾未闭合的行内标记（`**`、`*`、`` ` ``、`[`、`[[`）：从最后一个未闭合标记处截断，未稳定的尾部暂不渲染（不要显示半截 `**`）。
   - 未完成的链接 `[文字](ht`：暂不渲染 `[` 之后的部分。
   - 表格：最后一行若列数不齐或未以 `|` 结尾，先按段落渲染，下一段到达后再并入表格。
   - SETEXT 标题：流式期间把孤立的 `---` 当分隔线处理即可（GFM 惯例）。
3. 渲染 `stable`，尾部放一个细的"正在输入"光标（不是转圈）。每来一段就重算并渲染；用 `React.memo` 以 `stable` 为 key，避免每次 delta 全量重排。
4. 流结束时用**完整 buffer** 再渲染一次收敛，保证与最终 Markdown 逐字一致。
5. 中途中断：保留已收到的部分并说明"已保留实际收到的部分；不会自动重新发送"（SE 已有此文案，保留）。终止事件按 SE 现有的 SSE 完整性校验处理（request-id/sequence + 终止事件守卫）。
6. a11y：见 §5.5（`aria-live` 不得挂在增长容器上）。

### 7.4 阅读体验的其他硬规则

- 阅读页（点开一个页面）：页头 = 返回（"← 返回项目"或"← 返回知识"）+ 页面显示名 + 状态徽章（待确认 / 已确认知识 / 已被替代）+ 当前版本的唯一主操作（确认当前版本 / 确认新版本）。
- **不显示** `relative_path`；路径进「技术信息」折叠区，或只在 title。
- 已被替代 / 历史版本必须有明确提示：这条不能作为当前依据（SE 已有 `App.tsx:37-41` 的版本冲突文案，复用同一口径）。

### 8.1 断点表

| 断点 | 变化 |
|---|---|
| ≥1100px | 侧栏 200px + 主区 `max-width: 1200px` 居中；项目列表两栏可选 |
| 1101–801px | 双栏布局（目录/详情）→ 单栏；宽表格进入横向滚动容器 |

| ≤767px | 主区 padding 20px/12px；卡片 padding 16px；页头与工具行允许换行，主操作不换行到第二屏 |
| ≤640px | 所有多列网格单列；按钮整行（`width:100%`）；表格横向滚动；弹层 padding 10px、`max-height: calc(100dvh - 20px)` |
| ≤560px | 侧栏变底部 5 栏导航（高 60px，每项 44px，图标 + 12px 文案）；主区 `padding-bottom: 72px`；隐藏顶栏次要状态 |
| ≤380px | 正文 padding 12px；次要按钮收进「更多」；所有文案 `overflow-wrap: anywhere` |
| `@media (pointer: coarse)` | 所有按钮 / 页签 / 行内动作 ≥44px；图标按钮 44×44 |

### 8.2 验收（机器守卫 ⑩）

五档视口 **320 / 390 / 768 / 960 / 1280**，记录 `document.body.scrollWidth <= window.innerWidth`（即无整页横向溢出）；"内容容器内部横向滚动"（宽表格、页签栏）不算溢出。另需人工确认：200% 缩放可用、浅色/深色各一遍、`prefers-reduced-motion` 下无动画。

jsdom 量不到 `scrollWidth`，所以这一条**要么**引入 Playwright（`web/e2e/responsive.spec.ts`，五档断言 + 截图归档），**要么**保留为人工验收清单并在报告中逐档记录数值——不允许"没测就当通过"。

## 9. 工程细节的分级呈现

| 级别 | 内容 | 位置 |
|---|---|---|
| **L1 主界面** | 状态白话、下一步、数量、时间、中文显示名、费用的一句话结论 | 卡片/列表行；无 ID、无 hash、无路径、无 JSON |
| **L2 可展开** | 本次调用的服务与模型名、请求次数与上限、耗时、记录位置（中文名）、页面类型、读取时间 | `<details>`「本次详情」/「技术信息」 |
| **L3 只进诊断导出** | fingerprint、content_sha256、operation_id、candidate_id、page_id、request_id、`relative_path`、原始 JSON、错误原文、状态枚举 | 「高级与自定义 → 诊断」的复制/导出文本；**这是唯一允许英文与原始值的地方**（诊断文本必须精确） |

实现要求：

- L3 字段在组件里只能出现在 `title=` / `aria-label=` / `<details>` 内 / 诊断模块。守卫 ① 用一个显式的 `web/src/ui-contract.allowlist.json`（`"文件:字段": 次数`）把现有出现钉住，新增或减少都必须显式改 allowlist 并写明理由。
- 费用类文案统一模板：主位一句「这次会调用 <服务> <能力> 一次；<两句白话边界>」，数字进 L2。
- 「操作编号」这类标识符：L2 里以短码 + "排查时用"呈现，完整值进 title 或诊断导出（照 SWB 的 `shortId()` 做法）。

## 11. 机器守卫（10 条契约断言）

新建 `web/src/ui-contract.test.ts`（源码/CSS 扫描）、`web/src/ui-contract.render.test.tsx`（组件渲染）、`web/src/theme.test.ts`（对比度），并在 `web/package.json` 的测试路径下执行（`npm --prefix web test`）。
每条断言失败时的消息要写清"违反了哪条规则、看哪一节"。

| # | 规则 | 断言要点 |
|---|---|---|
| ① | 主界面不得出现内部 ID / hash / 文件路径 / 原始 JSON | 危险字段清单：`fingerprint`、`content_sha256`、`operation_id`、`candidate_id`、`remote_id`、`page_id`、`request_id`、`material_id`、`source_message_id`、`relative_path`、`.slice(0, 8)`。统计每个 `文件:字段` 出现次数，与 `ui-contract.allowlist.json` **精确相等**；且出现在 `<details>`/`title=`/`aria-label=`/诊断模块之外的实例必须为 0。另：组件 CSS 与 TSX 内联样式中不得出现裸 hex 颜色 |
| ② | 中文优先 | 渲染含英文 ID（如 `huoman-logistics`）的项目/主线/页面：可见文本（去掉 `title`/`value`/`aria-label` 属性后）必须含中文显示名且**不含**该 ID；ID 必须能在某个 `title` 里找到 |
| ③ | 字号不得低于 12px | 扫描 `web/src/*.css` 的全部 `font-size` 声明，< 12px 即失败（`.sr-only` 白名单）；同时断言 9/10/11px 的出现次数为 0 |
| ④ | 加载与空必须区分 | 对今日、审批、项目、问答四个视图 mock 一个永不 resolve 的 fetch：断言出现"正在读取…"（或骨架），且**不出现**任何空态文案；再 mock 空响应，断言空态文案出现 |
| ⑤ | 删除/断开类动作必须确认 | 对每个删除/断开控件：点击后出现 `role="dialog"`，且此时相关 API **未被调用**；点「确认」后才调用一次；点「取消」后仍为 0 次 |
| ⑥ | 正文与答案必须渲染 Markdown | 渲染含 `**粗体**`、`[[目标|标签]]`、`## 标题`、`| a | b |` 的正文：断言输出含 `<strong>`/标题元素/`<table>`，且可见文本不含 `**`、`[[`、`]]`。再跑流式用例：把同一段按 3 次分块喂入，断言**任何中间态**都不出现未闭合标记、不抛错，最终态与一次性渲染结果一致 |
| ⑦ | 深色对比度 ≥ 4.5:1 | 解析两套 tokens 的真实色值，计算 §6.2 列的 10 组 WCAG 比值并打印；低于 4.5（`control-border/surface` 低于 3.0）即失败 |
| ⑧ | 页面区块数量与顺序写死 | 导航恰好 5 项且标签精确等于 今日/审批/项目/知识问答/设置；今日恰好 2 个工具（记一句 / 导入会议）+ 3 个内容区，且顺序为 会议 → 待办任务 → 需要行动；设置主区恰好 3 张卡（工作库 / AI 模型 / 飞书）；并断言已退役内容（"飞书授权"按钮、待整理队列、审核稿、项目推进卡）不出现在今日 |
| ⑨ | 列表渲染不得调用模型（成本线） | 用 fetch spy 渲染今日/审批/项目/问答：断言渲染与刷新过程中**对 `/acceptance-plans`、`/intake/jobs`、`/index/plans` 等付费/外部端点的调用次数为 0**；只有点击显式按钮后才恰好 1 次。断言这些端点的字符串只出现在"确认"处理函数所在模块 |
| ⑩ | 五档无整页横向溢出 | Playwright（若引入）在 320/390/768/960/1280 断言 `body.scrollWidth <= innerWidth`；否则人工验收清单逐档记录数值（§8.2） |

要求：每条断言都要做**变异验证**——故意改坏实现，确认测试变红；否则断言不具备保护力（SWB 的教训：断言锚在写法上而不是行为上，会"测试全绿却发生回归"）。

## 13. 明确不要做的（SWB 用真实事故换来的）

1. 不要给每个功能加一个导航项；不要因为"能力存在"就给它一个页签。
2. 不要做独立的「决策台账」页：决策属于它所在的那条线（项目页的「决策记录」区块）；API 可以留，界面入口不留。
3. 不要把 Markdown / JSON / HTML 源码摊给用户。
4. 不要把英文 ID、内部枚举、错误码、异常原文放到可见位置（`TypeError: Failed to fetch` 这类绝不外泄；统一走 `errorText()` 之类的归一化）。
5. 不要在同一屏重复同一信息（同一计数只保留带"去处理"的那一处）。
6. 不要用红色横幅显示成功、取消或中性信息。
7. 不要让一个只读接口失败导致整页失败——分卡降级 + 保留上次成功值 + 标注读取时间。
8. 不要为了列表好看而调模型；只有显式按钮才花钱。
9. 不要把本地写入描述成"已同步到云端"。
10. 不要承诺不存在的恢复能力（"可以从历史找回"必须真的能）。
11. 不要保留"没有入口的能力"，也不要保留"没有实现的入口"：handler 与可见入口必须成对存在（SWB 曾有一个删除本机配置的 handler 活了几个月而界面上没有入口，用户根本无法删除）。
12. 不要在向导里用"通知"代替校验；也不要用"保存后自动联网"代替用户点击的检查。
13. 不要把业务判断交给模型（"这条结论该进哪一页"由用户选；AI 建议必须标「仅供参考」且不代提交）。
14. 不要让不可逆/外部动作自动填充或静默执行；默认不勾选、默认不发送。

## 13. 实施偏差与延后项（2026-10-14，切片 1 收口时由 Sol 确认）

实施中出现的规格内部冲突与已知延后，在此登记；规格与实现以本节为准，避免两处互相矛盾。

1. **浅色 `--muted` / `--accent` 最小加深（§6.1「保留现有颜色值」与 §6.2 4.5:1 冲突）**：按机器门优先，色相不变、只做达到阈值所需的最小加深——`--muted` `#717a79` → `#666f6e`（原比值 4.03），`--accent` `#b65a36` → `#a04d2c`（原比值 3.99），`--quiet` `#9aa19e` → `#6f7876`。D6 的「暖橙 + 墨绿侧栏」身份不变。
2. **`index.html` 引导脚本的 2 个颜色字面量为例外**：`meta[theme-color]` 与首屏前主题脚本必须在内联阶段写出颜色，无法读 CSS 变量；已在 `theme-tokens.css` 头部与 `index.html` 注释里互相指认。后续如改用构建期生成 bootstrap 可消除，属独立小改。
3. **间距字面量迁移延后**：`--space-*` 已定义并被尺度测试钉住，但 `App.css` 的 padding/margin/gap 仍在部分位置写 px。等 P1–P4 重写布局时一并迁移，避免在将被重写的布局上制造大 diff；届时应补一条「间距只用 `--space-*`」的守卫。
4. **`ui-contract.allowlist.json` 形态**：规格写 `"文件:字段": 次数`；实现为 `entries`（次数）+ 同键 `attribution`（归属切片与理由），并用断言强制两者键集合一致。允许清单只做基线，逐页清零由后续切片完成。
5. **守卫 ③ 比 §11 更严**：除「≥12px」外，另断言字号必须取 `--text-*` token（§6.1 的硬规则）；这是有意的加固，防止裸 px 回归。
6. **`App.tsx` 在切片 1 被触碰**（约 17 行）：D6/§0 把主题切换放在顶栏，且删掉 `font-size: 0` 需要把导航文案包成可 sr-only 的元素。P1 重写外壳时必须保留「首屏前三选 + 顶栏入口」这两条行为。
7. **`web/tsconfig.app.json` 的 `types` 增加 `"node"`**：守卫需在 jsdom 下读取真实源码；`@types/node` 原本就在 devDependencies，未新增依赖。
