# 浏览器黑盒观察（脱敏）

环境：本地 Vite 页面 `http://127.0.0.1:15173/`，工作库“QA 合成库 B”，本机 profile；仅合成页面与 MockTransport provider。通过浏览器可访问性树（AX）观察真实运行 UI。未能使用 Chrome DevTools MCP（当前工具不可用），所以 console 与 DevTools 网络面板为 NOT_RUN；本地 Uvicorn access log 和 provider MockTransport capture 作为网络请求旁证。

- 问答页展示“仅使用已确认知识”、本地索引 3 个页面 / 3 个分块；答复方式控件仅含“查找事实 / 跨材料比较 / 提出工作方案”，没有 current/history 范围入口。
- 对话历史中，先问“青岚计划目前的预算上限是多少？”，再问“它呢？”。第二轮没有引用，显示未找到合格依据；实际 provider 检索只嵌入当前问题，上一轮用户问题仅进入答案上下文，无法将“它”解析回青岚。
- 三种模式分别实际显示“已确认资料中的陈述”；比较模式另有“推断”；方案模式另有“建议”和“尚缺资料”。这是字段呈现观察，不证明模型语义正确。
- 历史回答中的青岚引用保留原 18 万元摘录，并显示“原引用版本已更新”；朱雀引用显示“引用版本仍可用”。
- 角色编辑器实际出现角色名、表达偏好、预算字节数、保存角色与角色选择；UI 明示角色只改变表达 / 指代理解，不改变证据或权限。
- 记忆面板显示待确认候选来自“本机历史中的本人问题；确认后才会用于回答”，并提供编辑文本和“确认并保存”；用户表达候选确认后出现在 provider payload 的 `user_memories`，pending 候选本身不进入该字段。工作库 B 中角色、候选、记忆的创建、选择、编辑、确认与删除均通过 UI/API 实际运行。
- 超预算角色请求由后端返回 HTTP 422 `context_budget_exceeded`，且未持久化消息；UI 却把它呈现为“本次回答 · 连接中断”。这是预算拒绝状态被误标，不是观察到真实网络断开。
- 历史列表说明“只保存在此 profile 和工作库”。

AX 观察不包含账户、真实材料或凭据；交互数据仅为合成内容。完整原始 HTTP / SSE/provider payload 见同目录 `raw-logs/` 与 `harness/`。
