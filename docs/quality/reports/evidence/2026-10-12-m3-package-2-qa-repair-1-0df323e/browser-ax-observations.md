# M3 包 2 repair 1 浏览器观察

受测浏览器：Google Chrome 访客 profile，真实 Vite WebUI (`127.0.0.1:15173`) 与 FastAPI loopback 服务，工作库仅含合成页面。通过 macOS 可访问性树读取和操作；不使用真实模型、外部服务、用户材料或凭据。

| 场景 | 操作和可见结果 | 状态 |
|---|---|---|
| current/history 入口 | 问答页“资料范围”可选“当前有效资料”或“包含历史版本”；后者出现“历史资料范围会包含已被替代或失效的版本，只供历史参考，不能代表当前规则。” | PASS |
| 历史效力 | 当前范围检索失效场地规则时未给失效页；历史范围下显示失效场地引用“已失效版本，仅限历史参考”、旧预算引用“已被替代的历史版本，仅限历史参考”。 | PASS |
| 重开后的引用可用性 | 将仅用于 QA 的失效页面文件移出工作库，切到新对话后重新打开原历史对话。引用标签同时显示“原引用已不可用 · 已失效版本，仅限历史参考”；当前页仍显示“引用版本仍可用”，旧预算继续显示 superseded 效力。 | PASS |
| 明确主体事实与新索引 | 在 UI 确认“青岚计划预算上限 18 万”和“朱雀项目预算上限 12 万”合成页，使用当前 fake fingerprint 建立 fresh index。直接问“青岚计划的预算上限是多少？”仅显示青岚当前页。 | PASS |
| 礼貌自然问法 | “你能告诉我青岚计划的预算上限是多少吗？”以及“我想知道青岚计划的预算上限。”均显示“没有找到能确认该对象的已确认资料。”；直接问法则命中。 | FAIL，缺陷 1 |
| 连续短追问边界 | 同一对话先直接问青岚预算；“它呢？”命中青岚当前页。继续问“它什么时候启动？”时支持证据同时出现青岚和朱雀当前页，故把无关主体排期作为本轮事实支持。 | FAIL，缺陷 2 |
| 对比 / 方案 | 对比青岚和朱雀设备采购预算时引用两页并将推断分开标注；方案请求将来源陈述、建议与“未提供执行负责人”的缺失信息分区显示。 | PASS |
| 422 预算反馈 | 将所选角色说明预算改为低于角色内容后提交；答案区显示“回答失败”和角色说明超预算的可读提示，没有“连接中断”措辞。问答历史列表没有新增失败请求。后端同场景的 `context_budget_exceeded` 422、provider 调用次数不变另有黑盒结果。 | PASS |
| 角色 / 记忆路径 | UI 创建、编辑、确认和删除角色；显式勾选“这是我本人表达…”后生成记忆候选，先编辑再确认；active memory 可编辑、删除。provider capture 中有已确认记忆，候选未进入活跃记忆字段；只有用户问题作为 previous-user-question 提示。 | PASS |

Chrome DevTools console 与 Network 面板在本轮工具环境不可观察；没有据此声称 console/request body 已在浏览器面板验证。真实 UI 的可见交互、服务端 loopback 日志和 Fake provider `MockTransport` 请求体 capture 是本轮实际证据。真实模型运行时元数据未暴露，标记 `UNVERIFIED`。
