## 缺陷

### SE-M1-QA-01 — 外部编辑后的正式页没有可完成的 UI 冲突/重新确认路径

- 代码 SHA：`f364c0122a1a74580009bf9342e6e864df6d975d`
- 案例：C08、C10；严重度：P1（正式知识外部编辑后无法通过已交付 UI 恢复并重新批准）
- 最小材料：只含合成文字的已批准页面，正文 `项目甲预算是 123 元`；第二份合成草稿目标设为该页面。
- 复现：
  1. 在 UI 确认第一份稿并索引页面。
  2. 打开第二份待审稿，将“整理到”选为第一份页面。
  3. 在工作库外部把 `123 元` 改为 `999 元` 并追加一行，保留原 approval。
  4. 回 UI 点击“确认并写入知识库”。
  5. 查看页面：正文被识别为待确认；打开页面详情没有确认控件。
- 预期：返回 409 / 明确差异，不覆盖外部内容；稿件仍可修订。用户能对外部修改后的当前正文重新确认，之后只把新版本用于当前问答。
- 实际：`PATCH /api/v1/drafts/<id>` 返回 422，UI 文案为 `Only confirmed knowledge pages can be updated`；页面正文不丢失，但 UI 无冲突解决或重新确认入口。旧内容检索被正确拦截。
- 证据：隔离路径 `.local/qa/2026-10-09-m1/page-before-external-edit.md` 与 `workspace/合成验收线/合成项目甲/模拟整理稿-1.md`；浏览器状态；FastAPI 日志；C08/C10。
- 建议边界：保留检索资格门禁；为 stale target 返回可操作的冲突状态，并在 WebUI 提供基于当前正文的重新确认流程。避免把外部版本静默覆盖或误认为已批准。
