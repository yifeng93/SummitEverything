## 实现范围

- 日志 / 思考仍使用 `POST /api/v1/journal/{kind}` 与 PageWriter。页面 ID 从 workspace UUID、kind、operation ID 稳定派生；writer journal 提供相同请求重放、异 payload 冲突与并发序列化。原始 HTTP 路由保持兼容。
- 记录类型分开的 UI、自由 Markdown、可选无关联 / 仅主线 / 主线加项目关联、明确保存、已保存页面重开与导航。
- `POST /api/v1/journal/assist` 只有用户明确点击时调用注入的 FakeLLM。建议在独立编辑区，不保存或批准；采用建议也只回填编辑区。ordinary save / list refresh 不调用 provider。超时错误不变更已保存正文。
- `POST /api/v1/projects/{project_id}/overview/confirmations` 使用现存稳定 overview_id；新建须显式确认，更新必须带 `expected_content_sha256`。旧基准返回 409 并保持原正文。概览路径由 PageWriter 依据项目注册表决定。项目进度需单独 Action API，不受知识确认影响。
- OpenAPI 导出并生成前端 TypeScript；同步 API / Workspace / Architecture 契约、README、验收案例、完整 v1 计划、进展账本与最新交接。

## 设计选择与风险

- 通过稳定随机空间内的 UUID5 页面 ID 来重用 PageWriter 的 durable transaction ledger，避免新增重复的 journal 写入算法；操作号跨库自然分隔。
- 概览更新以现有 `PageSnapshot.content_sha256` 作为 expected content version，与 PageWriter 的磁盘冲突检测对齐。调用者必须在重试一份 update 时保留同 operation ID / expected hash。
- AI assist 复用现有 fake provider `organize` 生成建议，没有新 provider 接口或依赖；真实模型 prompt / quality 尚无验收。
- UI 初次加载用 microtask 启动异步 refresh，以保留基线的三条 lint warnings 而不增加或隐藏 warning。
