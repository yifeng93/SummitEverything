# Stage B Provider Protocol Matrix

Reviewed: 2026-10-10 against linked first-party documentation and version-pinned official
SDK sources. This matrix records documented wire shapes, not account readiness or
real-service verification. No provider request was made while preparing it.

**Source-access note.** Feishu's documentation pages are dynamic, but the official site
publishes the same pages as raw Markdown when the path carries a `.md` suffix (for
example `https://open.feishu.cn/document/task-v2/task/list.md`). Every Feishu row below
was re-read through that first-party entry point on 2026-10-10, so endpoint, token type,
scope, parameter, pagination, size, time and error semantics are now quoted from official
prose rather than inferred from SDK DTO shapes. A capability whose exact semantics are
still unproven is marked **disabled** and cannot be reported as complete.

## Feishu

| Capability | Official source and documented mapping | Contract mapping / fixture | Open question / gate |
|---|---|---|---|
| Token parsing strictness | The token endpoints document `access_token`, `expires_in`, `scope`, `token_type=Bearer` and (with `offline_access`) `refresh_token`. The adapter requires the documented `expires_in` (positive), a non-empty effective `scope` and `Bearer` `token_type`; a missing required field is `malformed_response` and a first exchange without any refresh token is `missing_scope` -- no default is invented. Refresh requires a *new* ``refresh_token``: the documented value is single-use and the original is immediately invalidated, so a response that omits it or returns the consumed value is rejected. ``token_type`` must be exactly ``Bearer``, ``expires_in`` a positive finite integer, and the effective ``scope`` must come from that response. | Offline negative regressions cover each missing/malformed field plus the documented success shape, through the real parser and credential adapter (stored state and one-shot request counts asserted). | Whether the live account returns extra fields is untested; no live call has been made. |
| Authorize (code) | [获取授权码](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code): `GET https://accounts.feishu.cn/open-apis/authen/v1/authorize` with `client_id`, `response_type=code`, `redirect_uri`, `scope` (space-separated, ≤200), `state`, optional PKCE `code_challenge`/`code_challenge_method`. Success redirects to the registered `redirect_uri` with `code` and echoing `state`; refusal redirects with `error=access_denied` and `state`. Code is valid 5 minutes and single-use. | `authorization_url()` builds exactly these parameters; the callback keeps the registered scheme/host/port/path and a one-use 300 s state. | Whether the account's registered redirect list accepts the user's `localhost:8765/callback`. Real authorize remains a Stage C action. |
| Token exchange / refresh | [获取 user_access_token（v2 版本）](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token) and [获取 user_access_token（v3）](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3): v2 `POST https://open.feishu.cn/open-apis/authen/v2/oauth/token`, v3 (current, recommended) `POST https://accounts.feishu.cn/oauth/v3/token`. JSON body `grant_type=authorization_code` with `client_id`, `client_secret`, `code`, optional `redirect_uri`, optional `code_verifier`, optional narrowing `scope`. [刷新 user_access_token](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/refresh-user-access-token) uses `grant_type=refresh_token` with `refresh_token`. Response `access_token`, `expires_in`, `refresh_token` + `refresh_token_expires_in` (only with `offline_access`), `token_type=Bearer`, effective `scope`. `refresh_token` is single-use and rotates on every refresh; after 365 days the user must re-authorize. Errors: `20002` secret, `20003/20004/20065` code invalid/expired/used, `20037` refresh token expired, `20067` duplicate scope, `20068` scope not previously granted. | `exchange()`/`refresh()` post the documented JSON; `_tokens()` maps OAuth errors to `token_expired`/`missing_scope` and stores the rotated token. Fake reads the same contract. | Account-specific v2-vs-v3 endpoint choice; PKCE is implemented as optional (not enabled) because this is a confidential client with a stored secret. |
| Application (tenant) identity | [自建应用获取 tenant_access_token](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal): `POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal` with JSON `{app_id, app_secret}` → `tenant_access_token` and `expire` (max 2 h; a token with ≥30 min remaining is returned unchanged). No scope required. | `_application_token()` reads the secret from the shared vault slot, caches the tenant token until 60 s before expiry, and is used first wherever the endpoint documents tenant identity. | Whether the app has bot capability enabled for endpoints that require it. |
| User identity (minimal) | [获取用户信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/authen-v1/user_info/get): `GET https://open.feishu.cn/open-apis/authen/v1/user_info` with `Authorization: Bearer <user_access_token>` → `open_id`, `union_id`, `name`, avatars. `open_id` is the app-local binding; no scope required, phone/email are extra field scopes and are not requested. | `identity()` retains only `open_id`, `union_id`, `name`. A free-text account label is never treated as a verified Feishu identity. | Real identity fetch is part of the one-time OAuth connect; not run in Stage B. |
| Minutes metadata | [搜索妙记](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/minutes-v1/minute/search) `.md`: `POST https://open.feishu.cn/open-apis/minutes/v1/minutes/search`, query `page_size` (default 15, **max 30**), `page_token`, `user_id_type`; body `query` (≤50 chars) and `filter` (`owner_ids`, `participant_ids`, `create_time.start_time/end_time` ISO 8601 with timezone). Response `data.items[].token`/`display_info`/`meta_data`, `data.total`, `data.has_more`, `data.page_token`. Scope **user** `minutes:minutes.search:read`; requires `user_access_token`. Errors: `2094001`–`2094007`, `2094011/2094012` identity/token, `2095001/2095002` downstream. | `materials()` posts the documented body with `page_size` capped at 30, maps `token`→`material_id`, strips `<h>` markers from `display_info`, and maps identity errors. | The response carries no modification time, so `Material.updated_at` is optional rather than invented. The endpoint has **no visibility filter**; the adapter refuses a requested `visibility` filter instead of silently returning everything. |
| Selected minutes content | [导出妙记文字记录](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/minutes-v1/minute-transcript/get) `.md`: `GET https://open.feishu.cn/open-apis/minutes/v1/minutes/:minute_token/transcript` with `need_speaker`, `need_timestamp`, `file_format=txt\|srt`; returns a **binary stream**. `minute_token` is 24 characters. Auth: `tenant_access_token` **or** `user_access_token`. Scope `minutes:minutes.transcript:export` (the legacy `minutes:minute:download` is closed to new apps). Errors `2091001`–`2091006` including `2091005` permission denied. [获取妙记AI产物](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/minutes-v1/minute/artifacts) `.md`: `GET /open-apis/minutes/v1/minutes/:minute_token/artifacts` returns JSON with `summary`, `minute_chapters`, `minute_todos`, `keywords` and `transcript`; scope `minutes:minutes.artifacts:read`; same tenant-or-user auth. | `body()` downloads the transcript with the application identity first and falls back to the artifacts transcript only on `missing_scope`; both preserve raw bytes/hash and the source identity. Only UTF-8 TXT/Markdown is accepted downstream. | Arbitrary PDF/Word/image/OCR extraction is not claimed; only the documented text export is supported. Binary content-type of the transcript stream must still be confirmed against the live account. |
| Calendar | [获取日程列表](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/list) `.md`: `GET https://open.feishu.cn/open-apis/calendar/v4/calendars/:calendar_id/events`. `page_size` 50–1000 (default 500); `start_time`/`end_time` are **Unix seconds as strings**, return one page and **cannot be combined with `page_token`, `sync_token` or `anchor_time`**; `anchor_time` (Unix seconds) plus `page_token` is the paging path and also returns historical recurring instances. Response `data.items[]` with `event_id`, `summary`, `start_time`/`end_time` as `{date}` for all-day or `{timestamp (seconds), timezone (IANA)}`. Scope `calendar:calendar.event:read` / `calendar:calendar:readonly` / `calendar:calendar`; auth tenant **or** user. [查询主日历信息](https://open.feishu.cn/document/server-docs/calendar-v4/calendar/primary) `.md`: `POST /open-apis/calendar/v4/calendars/primary` returns `data.calendars[]` where each entry has `calendar.calendar_id`, `calendar.is_deleted` and `user_id`. | `calendar()` converts the explicit range to Unix seconds, requests `page_size = max(50, limit)`, validates every item, returns at most `limit` items, maps `timestamp`/`date` to UTC-aware datetimes, rejects a cursor for an explicit range, and reports `truncated` when the upstream page or `has_more` exceeded what it returned. `calendar_id()` parses the official `data.calendars[].calendar.calendar_id` list, skips the lookup when a calendar ID is configured, and refuses empty/deleted-only (`no_primary_calendar`) and ambiguous (`ambiguous_calendar`) responses. | An explicit range is one bounded page by protocol; cursor paging requires `anchor_time`, which changes the meaning of "range". Never widen the requested range on retry, and never present a partial result as complete. |

## Adapter and failure rules

- Settings, status reads, configuration previews, page reloads and provider selection do not contact external providers.
- HTTP adapters use bounded timeouts and a single cancellable overall deadline covering connect, response headers, body and end; cancellation happens at the transport level (live connection sockets are shut down), so it also covers a peer that never completes its header block. No automatic redirects, no retry for writes, response-size limits, strict response parsing and sanitized error mapping are preserved.
- OAuth pending state is bound to the authorization generation that issued it; a logout or a newer authorization invalidates it before any credential is written.
- A complete business operation holds a lifecycle lease; a provider retired by a configuration change finishes the operation it already started and closes its client only afterwards.
- Application (tenant) identity is used first; only the endpoints that document `user_access_token` as required (minutes search, task list) need the one-time user authorization. A missing scope disables only the affected capability and reports a user-readable reason.
- Real Feishu business reads stay server-disabled behind an explicit `feishu.real_data_enabled` flag until Stage C itemized authorization; the adapter itself is implemented and covered by HTTP stubs.
- No raw credentials, OAuth code/state, material content, task title, prompt, provider body, or authorization header enters logs or diagnostics.
- The tests use HTTP stubs and synthetic data only. They do not prove account access, model quality, actual cost or OAuth registration.
- Failed, timed-out, malformed or unverifiable writes retain the action as unknown. Reconciliation is read-only and cannot infer success from title equality.

## Narrow synthetic smoke authorization

The user authorized, on 2026-10-10, at most one DeepSeek chat, one Model Studio embedding, one Model Studio rerank, one Feishu code exchange and (only if needed) one refresh. The three model routes are separate from business operations, use fixed source-code synthetic payloads, reserve their attempt in an atomic profile-local ledger before transmission, and count failures/timeouts as consumed. The ledger is shared by all runs that use the same profile. General real model operations remain blocked. The Feishu smoke route is not implemented because the real OAuth adapter is now present but has not been exercised against the live account.

Model payloads are bounded: DeepSeek sends a fixed synthetic grounded-answer prompt and at most 64 output tokens; embedding sends one short synthetic string; rerank sends one short synthetic query and two synthetic candidates. The local smoke response reports only success/failure state and attempt count; it does not claim an itemized invoice. Using the 2026-10-10 DeepSeek peak cache-miss/output prices above and the fixed prompt's byte ceiling, plus the current [Model Studio pricing](https://help.aliyun.com/zh/model-studio/model-pricing) rates of CNY 0.50 / million input tokens for embedding and rerank, the conservative combined estimate is below CNY 0.01. Recheck prices before execution. Actual charges remain pending provider-side usage/billing confirmation. CNY 5 is the handoff's proposed ceiling, not a user-selected budget.

## 2026-10-11 离线收口传输契约

所有生产 adapter 使用 ADR 0007 的请求独立 DeadlineTransport。整体 deadline 包含 DNS/TCP/TLS/头/正文和关闭；返回前 runner 已结束，超时不误伤同 client 的其他请求。JSON wire 上限包含所有字段与转义；仅接受 identity 响应，其他编码在读正文前拒绝。不跟随重定向、不自动 HTTP 重试、不使用环境代理。注入 client 的实际 URL transport 同样须满足取消契约，MockTransport 仅为合成外部边界。

这些是离线实现证据，不证明账号权限、二进制 transcript content-type、全天日期服务器规范化或丢失写结果查询。真实任务写继续 disabled；已有有限 smoke 每项计数仍 0/1。

刷新单次消费必须跨进程重启：网络前在用户凭据原vault槽持久化本地refresh_consumed=true（不另存token摘要明文）；响应未知后不重发，合法轮换新token为false。官方refresh单次使用规则不允许因重启重置消费状态。
