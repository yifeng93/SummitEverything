# ADR 0012：今日与审批的连续整理体验

日期：2026-10-16。状态：Accepted。此 ADR 记录用户明确选择的布局与交互细节，不改变后端 API、内容信任规则、真实调用确认门或既有任务写入边界。

## 背景

原有今日和审批页面结构完整，但首屏不能同时承载日程/任务与记录入口；审批多组清单会把稿件正文、来源和结果回执挤在同一页，用户还需要依标题重新寻找保存结果。用户确认保留五栏导航，以真实日常动作重排今日，并让审批按来源、稿件、正式内容、索引和外部动作逐项处理。

## 决定

1. 今日桌面宽屏采用左日程与任务、右记录和导入；窄屏纵向排列。会议默认显示 3 条、任务默认 5 条，展开后仍可访问全部结果和原分页。首屏保证两区的首条业务内容、记事输入与导入入口可见。
2. 保存和导入只按 API 实际返回的来源 ID 接续。processing/reviewing 来源继续现有作业或稿件，不重复启动整理。
3. 审批保留五组固定顺序。待处理组默认展开，空组默认收起但可展开；组展开状态在专注页进入与返回间保留。来源、单份稿件和正式页面均可进入单项专注页。
4. 稿件默认为 Markdown 阅读；编辑、来源和差异按需打开。API 未持久化的冲突选择不显示为已保存，只在用户确认稿件时生效。API 刷新不得覆盖未保存正文；离开、打开正式页、切库和浏览器关闭需拦截未保存修改。
5. 首次索引 `not_ready` 时，如果服务端正式页面列表已有已确认页面，则将索引组计作待处理并展开。真空库仍可折叠。此为服务端状态的呈现，不复制索引资格判断。
6. 保留暖橙与墨绿视觉身份；删掉重复标题、首屏开发说明与位置导向文案。

## 后果

- 只改现有 Web UI 和行为测试，无新增依赖或后端接口。
- “正式内容已确认”与“首次索引已确认”继续是独立动作；界面回执保留真实 API 结果和准确正式页 ID。
- 视口验收使用至少 4 场会议与 6 项任务的非空合成数据；实现者自测不替代独立 QA。
