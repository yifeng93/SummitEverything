# ADR 0013：日常使用的界面收敛与热更新开发回路

日期：2026-10-28。状态：Accepted。此 ADR 记录个人自用阶段的两项改造：开发回路不再依赖重新打包安装，界面按「少废话、有主次、能收纳」重新整理。不改变产品边界、五栏导航、逐页区块顺序、内容信任规则或任何确认门。

## 背景

1. 每次查看界面效果都要重新构建甚至安装，反馈周期以分钟计；实际原因有三类：Vite 8 的原生绑定按安装时 node 架构选择，换 node 后直接报 `Cannot find native binding`；后端没有 `--reload`；原生壳只加载包内 `web/`，无法指向 Vite。
2. 日常页面把说明、技术身份和次级管理都放在第一层：今日两张卡各自只有一行按钮、审批五组各带一段说明、设置同一句「离线 Fake」重复三次、问答把历史/索引/角色排在回答之前、项目详情空档案展开五个「还没有记录」、时间线把正文标题当摘要渲染成整段内容。

## 决定

### 开发回路

1. `scripts/run_dev.py` 成为唯一入口，默认同时启动 `uvicorn --reload`（监听 `src/`）与 Vite HMR；前端改动即时生效，后端改动自动重载。
2. 启动时按当前 node 架构检查并补齐 `@rolldown/binding-*` 与 `@oxlint/binding-*` 平台包；不重装 `node_modules`、不改全局 npmrc。缺 node 时 API 仍可启动，由 Vite 子进程报告具体错误。
3. 开发状态固定在 `.local/dev/`（profile + 工作库），启动后自动打开并记录一次「首次配置完成」，直接落在今日；`--fresh` 清空，`--no-workspace` 回到选择页。只有仓库内开发 profile 会这样做，集成测试注入的临时 profile 不受影响。
4. `--app` 编译并启动 `native/` 的 debug 壳，用 `SUMMIT_DEV_SERVER_URL` 指向 Vite；生产包仍走内置后端与包内 `web/`，不读取该变量。

### 界面收敛

1. 样式按页拆分到 `web/src/styles/`，`App.css` 只保留外壳与共享按钮/表单/提示；新增 `.panel`、`.section-head`、`.pill`、`.disclosure`、`.empty-row` 等共享结构，页面不再各自发明间距与字号。
2. 去掉页面级 `eyebrow` 口号；每页只保留一个标题和一句说明。设置与问答使用较窄的居中内容列，避免宽屏下大片空白。
3. 今日：会议与待办合并为一张「今天的安排」卡，各区块自带标题和唯一的次级刷新动作；记录、导入与最近材料留在右侧一张卡。
4. 审批：五组固定顺序不变，收起时只显示编号、标题和数量；说明移入展开后的正文。筛选改为分段按钮，去掉常驻的规则段落。
5. 设置：三张卡保留；能力清单压缩为「名称 + 状态」，相同的「离线 Fake」/「需预览确认」说明合并为一条脚注，下一步动作收进折叠区。高级与自定义仍默认收起。
6. 问答：提问区之后立刻是回答与出处，历史、索引、角色与记忆收进底部三条折叠行；提问成功后清空输入框。
7. 项目：列表与页头共用同一左边界；全部档案为空时只显示一行引导；时间线摘要只取第一行纯文本，剔除行内代码与链接目标，避免把正文或内部标识复制到列表。
8. 阅读页的「移动页面 / 插入链接」保留可见，但加「整理页面」小标题，与正文分层。

## 后果

- 无新增运行时依赖；`watchfiles` 只加入 dev 依赖组。
- 原有 243 条前端测试与开发脚本集成测试继续通过；两条 brittle 断言改为等待设置加载、用正则匹配空态文案，未放宽任何验收门。
- `--app` 只用于本机调试，不进入交付包；打包与安装验收流程不变。
