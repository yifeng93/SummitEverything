# ADR 0015：标题即功能，取消页面与区块的二级描述

日期：2026-10-28。状态：Accepted。此决定改变前端文案层级，不改变任何业务状态、确认门或数据边界。

## 背景

页面在 h1 下统一挂一句 `.lede`，卡片标题下再挂一段说明，审批每个分组展开后又重复一遍职责。用户指出：这些说明不随状态变化，标题本身已经能说明功能，重复描述反而让主操作和真实状态不突出。用户要求「用功能的方式直接说明，不要反反复复地加描述文案」。

## 决定

1. 页面 `h1` 下不再有 `.lede`；`PageHeader` 删除 `description` 字段，从组件层面禁止再加副标题。
2. 卡片与区块标题下不再放静态说明。删除今日「记录与导入」说明、设置三张卡的说明、审批五组的分组说明与页级规则段、项目「默认排序…」说明、问答提问区的「只使用已确认知识…」说明。
3. 首配向导第 2–5 步删除静态步骤说明；必要信息由字段标签、状态徽章、确认弹层和错误提示承担。
4. 以下内容保留，因为它们会变化或与具体动作绑定：加载/空态/错误、保存回执、最近读取时间、数量徽章、确认后果、危险操作说明、字段级校验。
5. 判断标准：删掉这句话后，用户是否仍知道该点哪里。知道就删；不知道则先改标题，而不是补一段说明。
6. 政策类边界（原件不进入检索、真实调用需确认、密钥只进钥匙串）不在每个页面顶部重复，只在对应操作的范围预览或确认弹层出现时说明。
7. 唯一保留的授权限定语是飞书卡在「已授权」时的一行脚注：「已授权读取；不表示身份已核实，也不能写回飞书任务。」它随状态出现，不是固定说明。

## 后果

- 五个主页面与首配向导的首屏信息密度明显下降；标题、状态和按钮成为唯一层级。
- `PageHeader` 的 API 变窄；后续页面若需要解释，只能把话放到具体控件旁，不能重新引入页头副标题。
- `ProjectsView.test.tsx` 中一条只检查「默认排序…」静态文案的断言随文案删除；搜索/筛选/返回位置的行为断言保持不变。
- 样式表删除 `.section-note`、`.query-note`、`.approval-group-desc` 与排序说明的死规则。
