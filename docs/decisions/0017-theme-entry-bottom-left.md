# ADR 0017：主题入口移到左下角「外观」弹出层

日期：2026-10-28。状态：Accepted。只改主题控件的入口位置，不改主题三选、持久化键或深色解析规则。

## 背景

顶栏右侧同时放保存状态和主题下拉，和左上角的「设置」导航重复；用户日常切主题的频率远低于读页面，顶栏长期占用一个控件不划算。用户要求把主题移到左下角，用一个「设置」类入口打开，下拉/弹出即可。

## 决定

1. 顶栏右侧只保留保存三态；移除 `<select aria-label="主题">`。
2. 侧栏底部工作库、本机状态下方新增「外观」按钮（`Palette` 图标 + 文本），点击在按钮上方弹出 `跟随系统 / 浅色 / 深色` 三选；当前项带 `Check`，`aria-pressed` 表达状态。
3. 弹出层是 `role="dialog" aria-label="外观与主题"`；支持点外部关闭、Escape 关闭并把焦点还给按钮；选择后立即应用并关闭。
4. 主题状态仍由 `useThemePreference` 单一持有；持久化键 `sx:theme-preference` 与 `index.html` 首屏脚本不变。
5. 侧栏改为 `position: sticky; height: 100vh`，保证左下角入口在长页面滚动时仍固定可见；≤560px 移动底栏布局保持原样。

## 后果

- 顶栏更安静；主题入口只出现在左下角，不再重复。
- 页面就绪标记从「主题下拉」改为「外观与主题按钮」；`AppShell`、`App.shell`、`ui-contract.render` 的主题测试同步改为打开弹出层再点选项，行为断言不变。
- 主题三选仍是深色一等公民的机器守卫对象，未降低验收门。

## 同日追加：移除「仅本机运行」

侧栏底部的「仅本机运行 / 本机服务未连接」是一句长期常驻但不可操作的提示；服务真的不可达时，应用已经会显示专门的错误页和重试入口。用户要求去掉。侧栏底部只留工作库与「外观」；`service-status` 的数据仍供请求层记录可达性，不再有常驻展示。
