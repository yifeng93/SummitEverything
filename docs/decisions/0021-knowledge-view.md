# ADR 0021：知识库概览与按来源分组

- 状态：采纳
- 日期：2026-10-28
- 范围：仅「项目」页的信息组织，不改变页面、确认门与检索语义。

## 背景

项目详情原先把关联页面排成一条时间线。它对按日期推进的项目成立，但用 151 篇官方文档做真实语料后，这条时间线变成 151 行同质条目：看不出有哪些类别、每类多少、哪些进了索引。索引状态只在「审批 → 索引」里显示一个总数，用户无法判断「我导进去的东西到底被检索覆盖了多少」。

## 决策

1. 项目页顶部增加概览条：已确认页、已索引页、分块、待更新，右侧一行状态文字。数据来自 `GET /api/v1/index/status`；任一字段缺失时显示 `—`，不推测。
2. 项目详情把「时间线」改为「页面」，按 `source_path` 的末级目录分组（`docs/subsystems/x.md` → 子系统）。没有 `source_path` 的页面按 `kind` 归入推进日志 / 关联会议 / 主题 / 其他页面。大组在前，组内保留原有时间顺序。
3. 概览条只在需要处理时追加一行状态文字（`尚未建立索引` / `索引待更新 · N 页` / `索引状态暂不可用`）。索引正常时不显示状态句：四个指标已经说明覆盖范围，「仿真/真实向量」只是设置里运行模式的复述，又是工程词，按 FRONTEND-GUIDE §3、§4 不进日常界面。
   - 2026-10-28 用户反馈后修正：原第 3 条要求用状态文字区分「仿真向量 / 真实向量」，被判定为无意义且破坏概览布局，作废。后端仍下发 `vector` 字段，前端不再展示。
4. 导航仍是五项，不新增「知识库」页。项目总览本来就是知识入口，另开一页会产生两个入口。

## 后果

- 分组质量取决于导入时写入 `source_path`。没有该字段的来源（手写页面、会议、日志）会落到类型分组，这是可接受的降级，因为它们的组织维度本来就是时间而非目录。
- 未建索引时概览条显示 0 与「尚未建立索引」，不用空白伪装成正常。
- `vector` 字段是粗粒度描述，不承诺 provider 细节；真实 provider 切换后无需改前端。

## 依据

- 真实语料：DeepSeek Harness 官方文档 151 篇，152 页 / 3530 分块。
- 前端守卫：`ui-contract.test.ts` 守卫①（内部标识）、守卫③（字号 token）。
