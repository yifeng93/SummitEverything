# ADR 0027：页面详情只读，内容由外部来源写入

日期：2026-10-29。状态：Accepted。用户明确：页面详情只渲染 Markdown，不允许在这里编辑或新增正文；Markdown 在外部来源（仓库文件）里改动，本应用只负责发现新增/变化，并决定要不要索引。此 ADR 收回 [ADR 0022](0022-reading-directory-and-page-actions.md) 第 3 条里「插入页面链接」的部分。

## 背景

页面阅读页原先支持两种写操作：

1. 待确认页可以展开「编辑 Markdown 源码」，直接改标题与正文后再确认；
2. 已确认页的「页面操作」抽屉里可以「插入页面链接」——把一段相对链接追加到正文，再走「确认新版本」。

这两件事都让应用承担内容编辑：一旦允许在应用内改正文，就要处理与外部来源的冲突、版本合并、重新确认时的差异展示，以及「确认后的正文和文件里的正文不一致」这类问题。而产品定位是：内容在外部维护，应用监听变化、确认版本、建立索引。

## 决定

1. **页面详情只读**：已确认页与待确认页都只渲染 `<MarkdownText>`，不提供 `textarea` / `input` / 编辑器入口。
2. **移除「插入页面链接」**：正文不再由应用追加内容；内部链接仍按原文渲染并可点击跳转。
3. **待确认页只保留「确认当前版本」**：看到外部写入的新版本，确认它进入检索；不提供改写。文案明确「正文由外部来源写入，这里只读；需要改动请到来源文件，保存后回来重新确认」。
4. **「页面操作」抽屉只保留「移动到其他项目」**：这是归属整理，不触碰正文；移动仍需二次确认。
5. 草稿（审批）流程不变：它负责把新导入内容整理成待确认页面，不属于「页面详情」。

## 后果

- `PageReader` 删除 `title` / `body` 本地状态、`addLink`、链接选择器与插入后的确认面板；确认请求直接用 `page.metadata` 与 `page.body`。
- `reader.css` 删除 `.page-source-editor` 与 textarea 相关规则。
- `PageReader.test.tsx` 的「插入链接」用例改为只读断言：没有 textbox、没有「插入链接」，抽屉里只有归属。
- 内容冲突不再由本应用处理；外部文件改动后，页面变为待确认，用户在阅读页核对后点「确认当前版本」。
