# ADR 0023：侧栏「项目」二级入口

日期：2026-10-29。状态：Accepted。用户要求能够从侧栏直接打开具体项目，而不是每次都先进项目列表再点一次。此 ADR 只改外壳导航，不新增导航目的地，不改项目/页面的数据模型。

## 背景

侧栏「项目」是一个目的地，进去后还要在列表里找目标项目。实际使用中项目数量很少（官方文档、书法首客），每次两步的操作是纯损耗。用户直接在截图里圈出「项目」下方，要求把这些项目作为二级菜单列出来。

同时存在一条既有硬规格：主导航恰好 5 项、顺序固定（D1），不得加第 6 项。二级入口必须在不破坏这条规则的前提下加入。

## 决定

1. 在「项目」下方列出**未归档项目名**，点一下直接打开该项目详情；空工作库时不占位。
2. 二级项不进入 `NAV_ITEMS`，不计入 5 项；`aria-label="项目快捷入口"` 的独立列表承载它们。
3. 当前打开的项目用 `aria-current="page"` + 2px 强调条标记；父项已经是填充态，二级项不再填充背景，避免父子抢层级。
4. ≤800px（64px 图标栏）与 ≤560px（底部 5 栏）不显示二级项，只在桌面侧栏出现。
5. 侧栏数据由外壳读取 `GET /api/v1/projects` 并只保留未归档项；项目新建、重命名、归档后由项目页通知外壳刷新。
6. 点二级项与点导航走同一套未保存稿件拦截：审批里有未保存修改时先确认再离开。

## 后果

- `AppShell` 增加 `projects` / `activeProjectId` / `onOpenProject` 三个可选属性；`ProjectsView` 增加 `target`、`onTargetHandled`、`onActiveProjectChange`、`onProjectsChanged`。
- 项目页通过准确 id 打开详情，不按名称匹配；目标项目不存在时结束这次跳转。
- 导航守卫从「数 `<nav>` 里所有按钮」改为「数 `.nav-item`」，语义仍是 5 个目的地；新增用例覆盖二级项存在时仍是 5 项。
- 顶栏路径仍显示「项目」，不因二级入口改变；项目名在侧栏高亮里体现。
