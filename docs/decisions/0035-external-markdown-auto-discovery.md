# ADR 0035：自动发现外部 Markdown 变更

日期：2026-10-30

## 决议

- 应用对工作库内登记项目目录与工作日志/思考目录中的 Markdown 文件做轻量 revision 轮询；不增加 watcher 依赖，也不扫描来源、草稿或系统目录。
- 后端 revision 绑定当前认证会话和 `X-Summit-Workspace-Id`，只返回工作库 ID 与不透明摘要。服务端只检查 manifest 和文件目录 stat，不在每个轮询周期解析 Markdown 正文。
- 前端约每 1.5 秒轮询，发现变化后短暂合并连续保存，再定向刷新正式页面目录、项目概览、审批页面与索引状态。工作库/ profile 切换时终止旧轮询及在途读取；组件保持挂载，避免丢失滚动和无关草稿。
- 单次 revision、正文、目录或索引读取均有请求超时；项目内联正文读取失败最多自动重试三次（每次使用新的请求与超时），其余页面/目录/索引读取失败最多自动重试两次。耗尽后显示可重试的错误状态，之后文件 revision 改变或用户显式重试会重新读取，不无限轮询失败接口。
- 新增/修改页进入待确认；删除或暂时无效的页面明确显示不可用，文件修复后自动恢复。变更检测不批准、不索引、不调用模型或飞书；索引首次确认门及后续增量规则不变。
- PageReader 与项目概览只读。概览已有确认入口；缺少概览时提示用户从外部 Markdown 建立，不提供内嵌正文编辑器。
- 每次问答仍独立读取当前文件并执行现有资格校验，revision 仅用于界面同步，不替代读取时间的安全门。

## 取舍与边界

轮询以少量文件 stat 换取实现简单和跨编辑器兼容；大型工作库的轮询成本需用目标规模验证。revision 不包含正文、路径或 approval proof，不能作为确认凭据。目录读取遵守现有 `list_pages` 事务语义；若一个文件无效导致目录整体失败，列表、树和确认入口显示暂不可用并保持确认关闭，修复文件改变 revision 后重新读取恢复。
