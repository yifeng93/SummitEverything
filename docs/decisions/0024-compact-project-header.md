# ADR 0024：项目详情顶部三行与折叠档案

日期：2026-10-29。状态：Accepted。用户指出项目详情顶部占掉近半屏，页面列表才是主体，要求压到「三个标题那么高」，并把没有意义的空态描述收起来。此 ADR 只改项目详情的排布，不改档案内容、确认门或页面数据。

## 背景

项目详情原来的顺序是：返回链接、大号 eyebrow（线条目）、h1、徽章、一整行三个操作按钮、档案区（空时是一整句「档案还没有内容。追加推进日志或创建项目概览后…」）、项目概览（空时是「还没有项目概览。」+ 创建按钮）。空项目打开后，真正的页面列表被压到首屏以下，用户要先滚过三段空态文案才能看到页面。

## 决定

1. **顶部固定三行**：返回行（返回链接 + 线条目，竖线分隔）→ 标题行（项目名 + 徽章，右侧同一行放追加推进日志 / 存产物 / 更多）→ 档案摘要一行。合计约 120px 内容高度。
2. **档案与概览默认折叠**成一行摘要：`当前状态：… · 下一步：…`，各取首行、单行省略；没有内容时摘要显示「补充档案与概览」。展开后才是五个档案区块与项目概览。
3. **删掉空态说明句**：不再渲染「档案还没有内容…」「还没有项目概览。」；空块只在展开后显示「还没有记录」。
4. **正文按 72ch 收窄**：详情容器沿用 `.content-wrap` 的 1200px（页面区两栏需要），档案段落与概览正文限制 `--measure-read`，避免长行。
5. 移除标题上方的 eyebrow；线条目并入返回行，不再单独占一行。

## 后果

- `ProjectDetailView` 的结构变为 `.project-detail-topline` / `.project-detail-head` / `.project-facts`（details）/ `.page-list-section`。
- `.project-detail` 不再声明 900px——它本来就被 `.content-wrap` 的 1200px 覆盖，原声明从未生效；这里改成显式 `max-width: none`，避免继续误导。
- 「下一步」在折叠态只保留首行；完整内容需要展开，这是用纵向空间换首屏可读性的取舍。
- 规格 §5 的区块顺序、不做什么与验收点同步更新；测试无需改动，`<details>` 内容仍在 DOM 中。
