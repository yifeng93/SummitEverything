# ADR 0031：本地检索与 DeepSeek 生成

- 状态：已接受
- 日期：2026-10-29
- 决策人：用户

## 背景

产品此前配置了云端 embedding 与 rerank provider，导致索引和检索依赖供应商账号、密钥与额度。用户明确选择「最终也不用百炼，改成本地检索 + DeepSeek」。

## 决策

- 向量化、混合召回和语义排序全部在本机完成；整理和生成式问答仍由 DeepSeek 完成。
- 固定使用 `BAAI/bge-small-zh-v1.5`、公开 revision `46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59`、512 维。真实运行只读取工作库外、本机 profile 内已准备好的模型文件，禁止隐式联网下载及模型缺失时的远端回退。测试注入路径可以在 profile 外部。
- 首次下载是用户在设置中明确启动的动作。文件必须按固定 size/SHA-256 校验，先下载到同目录暂存，再原子切换；失败状态可见且可重试，不能覆盖先前有效模型。
- 长文本使用最多 480 token、重叠 64 token 的窗口，保留原始文本切片并为索引窗口建立稳定 ID；模型 revision、维度、窗口和聚合规则绑定进索引 fingerprint。
- 本地搜索不需要 DeepSeek key。生成式对话只为 DeepSeek 创建一次性请求授权；本地索引预览、构建与排序不产生付费请求计划。
- 旧 DashScope 配置仅为读取兼容；运行时拒绝使用云端 embedding / rerank。用户明确切换到本地配置后保留原钥匙串密钥，不自动删除。
- 新用户默认选择本地检索。旧 Fake 依然是明确的测试 provider，不可冒充实际本地模型。
- 首次索引、模型更换、全量重建仍展示页面与版本范围并由用户确认；同模型批准内容的增量索引可依既有本机规则执行。

## 影响

- 512 维本地向量与旧 Fake / 1024 维云端索引 fingerprint 不同，不能混用；切换后须显式准备完整新代。
- 设置、首次配置与能力状态显示本地模型缺失、准备中、就绪、失败等状态，并区分 DeepSeek key 状态。
- 必须在离线网络阻断下测试真实本地模型的检索与长文本尾部事实；小型合成语料不能支持普遍效果承诺。
- DMG 目标仍为 macOS 13。打包固定 Python 3.13，选择兼容 macOS 13 的 ONNX Runtime wheel；Python 3.14 的开发 wheel 要求 macOS 14，不改变 DMG 目标。
- 真实 DeepSeek 请求仍是单独授权与验收门；不通过本地检索验收推断 DeepSeek 质量、Keychain、DMG 或真实业务资料通过。
