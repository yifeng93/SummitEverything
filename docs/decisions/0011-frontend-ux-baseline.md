# ADR 0011：前端体验基线（导航、信息分级、阅读与深色）

日期：2026-10-14。状态：Accepted（记录用户以三轮选择题确认的界面口径；不改变 Fake 默认、真实调用确认门、密钥边界或任何验收门）。

## 背景

用户在本机只读参考项目 SummitWorkbench（SWB，`f9e9439`）上经过了 8 轮界面优化与真机验收。对照后发现 SummitEverything 的界面虽然结构完整，但缺"用户友好"的思维：集成与调试面板排在核心动作之前、内部 ID/hash/JSON/文件路径直接进入可见文案、正文与模型答案按 Markdown 源码等宽显示、删除类动作零确认、44 条字号规则 ≤10px（最小 8px）、深色模式在最新的设置/向导 CSS 里实际不可读、首次体验被拆成"全屏工作库选择 + 设置里的 5 步向导"两条且向导每次从第 1 步重开。

用户在 2026-10-14 以三轮选择题确定了目标形态。决议原文与逐项理由见 [前端优化指南](../product/FRONTEND-GUIDE.md) §2；逐页结构见 [逐页规格](../product/FRONTEND-PAGE-SPECS.md)。

## 决议

1. **导航为 5 栏**：今日 / 审批 / 项目 / 知识问答 / 设置。「日志与思考」并入今日的工具区；「飞书日常」不再占导航项。2026-10-15 用户批准设置页连接/重新授权入口复用首次配置向导第 4 步；今日旧授权入口迁移归 B 切片，不另起 OAuth 流程。
2. **审批页集中所有需要用户确认的事项**：待整理的来源、待复核的稿件、待确认的正式内容、待确认的索引更新、待确认的外部动作，按"先整理 → 再复核 → 最后确认"分组并显示数量。
3. **工程细节分级**：主界面只说白话结论与下一步；可展开区放服务/模型/次数/耗时/记录位置；fingerprint、`content_sha256`、operation/candidate/page/request id、`relative_path`、原始 JSON、错误原文只进诊断导出。诊断导出是唯一允许英文与原始值的地方。
4. **文案白话优先、中文优先**：每页一句"想做什么就点哪里"；术语替换为白话，必要术语进括号；可见文本不含英文项目 ID 与内部标记；只有「引用来源」保留完整路径。高风险文案必须声明"不会发生什么"。
5. **阅读体验**：正文与模型答案一律渲染 Markdown，支持**流式边到边渲染并对未写完的语法容错**；实现采用 `react-markdown` + `remark-gfm`，不启用原始 HTML 渲染；正文用系统无衬线（等宽只用于代码/路径/ID），阅读列宽 72ch。
6. **交互反馈**：toast（成功/失败/中性）+ 按钮 busy 改文案 + 删除/断开/覆盖必须确认；付费与外部动作保留现有的一次性范围预览与独立确认，但把请求次数/预算/价格公式降级到折叠区。
7. **三态分离**：加载、空、错误是三件事；读取中不得显示空态文案；单个只读接口失败只降级该卡片并保留上次成功值。
8. **样式系统**：补齐尺度 tokens（间距/圆角/阴影/字号）并禁止组件内裸色；字号下限 12px；深色模式为一等公民，提供 跟随系统/浅色/深色 三选并在首屏前应用；颜色对比度以机器断言（WCAG ≥ 4.5:1，控件边框 ≥ 3:1）。
9. **骨架保留左侧栏**（5 项，200px），重做尺寸、层级与窄屏行为（≤800px 图标栏且必须有 `title`，≤560px 底部 5 栏，粗指针 ≥44px）。项目页改为"一页列表 → 点进项目详情页"，返回时恢复搜索、筛选与滚动位置。
10. **首次配置合并为一条可中断续接的向导**：工作库 → 密钥 → 连接检查 → 飞书授权 → 今日；工作库是第 1 步并优先用原生目录选择器；设置入口复用同一宿主和向导步骤；必填缺失时禁用主按钮而不是用通知代替校验；首屏不再把"接口报错"当成"没有工作库"。
11. **规则写成契约测试**：10 条守卫（内部标识不外泄、中文优先、字号下限、加载与空分离、危险动作确认、Markdown 渲染与流式容错、深色对比度、页面区块数量与顺序、列表不调模型、五档无横向溢出），每条都要做变异验证。

## 与既有决议的关系

- 细化 [ADR 0010](0010-first-use-configuration-ux.md)：其 §3 声明的"向导可中断续接"在本 ADR 决议 10 落地前**记为未实现**；§1 的三卡主区与 §5 的显式连接检查在本 ADR 中保持并扩展（危险动作确认、逐卡降级、深色）。
- 不改变 ADR 0009 / 0010 的凭据边界：密钥仍只在本机录入一次并存 macOS Keychain，不打入包、不写仓库、不通过聊天传递。
- 不改变 PRODUCT-SPEC 中"默认 Fake""真实调用需一次性范围预览与独立确认""正式内容须用户确认当前版本""飞书任务写保持禁用（在缺少可核实写结果的能力时）"等条款。
- 界面改动不构成任何阶段通过与验收结论；真实 provider、飞书 OAuth、Keychain 生命周期、安装/公证、五日与双机仍为独立未测门。

## 2026-10-15 实施澄清（用户已批准）

- 统一向导由应用级宿主持有：无工作库先做第 1 步，打开后在同一流程继续第 2 步；不先进入设置页再弹出另一向导。第 1 步关闭回欢迎连接页，工作库打开后关闭回来源业务页。
- 非秘密进度只在取得服务端真实 profile 与 workspace 身份后按两者隔离保存。向导仍打开时页面重载自动恢复原步骤；用户显式关闭后不自动弹，但设置可以手动续接；完成后不再自动打扰。
- 设置页工作库入口回共享向导第 1 步，Feishu 连接/重新授权入口直达同一向导第 4 步。今日原有授权入口迁移至 B；此澄清不改变 Fake 默认、显式范围确认、真实任务写禁用或授权安全规则。实现固定产品 SHA `9ed544ab5cfcbf21b6e81290a4bf0c5a9825e9ad`，开发者报告与独立 QA 结论另行记录，不代表本 ADR 宣告验收通过。
