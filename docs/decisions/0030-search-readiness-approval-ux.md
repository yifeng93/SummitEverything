# ADR 0030：审批中的搜索准备状态

日期：2026-10-29。状态：Accepted。此决策只调整审批区文案和交互，不改变索引 API、检索资格、模型调用或授权规则。

## 背景

用户无法从原“索引”区理解它与搜索问答的关系，也无法判断是否每次都要操作。正常状态应明确说明无需操作；只有待准备、待更新或配置变化时才显出下一步。

## 决定

1. 审批第五组顺序不变，标题改为「搜索与问答准备」。清楚说明其用途：让已确认内容可被搜索和问答找到。
2. ready 且搜索配置未变化时，显示“内容已是最新，无需操作”和已准备页数；不显示范围预览、重建按钮、token 或技术计划。高级维护可显式查看全量重建范围；打开折叠区本身不请求计划。
3. 首次准备能否执行以已成功读取的正式页面列表中的 confirmed 页面为准。无 confirmed 页面时不能首次准备或全量重建；页面列表未读完/失败时提供刷新且不将其当空库。
4. stale / manual_required 显示待更新入口。active 与 configured fingerprint 不同则优先显示搜索方式已更换及重新准备范围入口。未知状态和未读取的搜索配置不伪装为 ready。
5. 服务端增量计划的 `page_ids` 表示检查范围，不一定是变化页；文案明确仅处理有变化的内容。Fake 计划只读预览、显式确认后执行，不创建 acceptance-plan。Real 计划必须先创建并确认 acceptance-plan，包含可能发送的页面内容、模型用量与请求上限；授权预览失败不开放执行。取消预览确认不执行。
6. Fake/演示模式仅代表操作流程可体验，不代表真实检索和问答质量已可用。

## 后果

- UI 继续复用 `/index/status`、`/index/plans` 与 `/index/jobs`，不改后端计数或范围计算。
- `current_pages` 是当前合格正式页数，`pages` 是已索引旧代页数，`stale_pages` 是两集合版本差异并包括删除项；不将它们混作计费/变更页数。真实计划的逐页标题预览可能为空，确认文案因此描述范围数量与处理方式，不承诺总能显示页面标题。
- 实现与验收证据仅覆盖合成模式和既有明确授权门；真实模型调用和真实账单仍需独立验证。
