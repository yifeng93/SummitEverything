# ADR 0022：阅读页目录与页面操作分层

日期：2026-10-28。状态：Accepted。用户明确否定了「打开页面后看不到目录、正文尾部就是移动到项目」的做法，要求先有位置感再读内容。此 ADR 不改变后端 API、内容信任规则或确认门。它在展示层修正 [ADR 0021](0021-knowledge-view.md) 的第 2 条：按 `source_path` 分组的口径不变，但项目详情与阅读页都改为「左目录 + 右内容」两栏，不再纵向平铺。

## 背景

页面阅读页原来是单列：返回链接、状态、标题、正文，末尾跟一条「整理页面」，里面是两个空下拉框（移动到项目、选择已确认页面）和两个按钮。用户在一份已确认知识读完的地方被要求整理页面，既没有目录上下文，也不知道自己位于哪条线、哪个项目、哪个分类。

同一时期，项目详情页把关联页面按来源目录分组后**纵向平铺**：24 页的分类就是一长串，只能靠滚动寻找。阅读页与项目详情因此都没有真正的目录结构。

`FRONTEND-PAGE-SPECS.md` §4 曾写「不做两栏目录（D12）」，与用户本次的明确要求冲突；该条按本 ADR 作废。

## 决定

1. **阅读页改为左目录、右正文**：左栏 224px 显示 `项目 → 分类 → 页面`，当前页高亮，当前分类默认展开；≤1100px 时收起为「目录」按钮，点开右侧抽屉。正文列保持 72ch。
2. **补面包屑**：`项目 / 分类` 只读展示，替代原来只有一个「返回项目」按钮、无法判断层级的做法。
3. **已确认页的正文区只读**：不出现 `select`、`input` 或表单按钮。移动归属收进右上角「页面操作」抽屉；移动前显示当前归属与后果并二次确认。
   - 2026-10-29 修正：原第 3 条还包含「插入页面链接」，该能力已由 [ADR 0027](0027-page-detail-is-read-only.md) 收回——页面详情不编辑、不新增正文。
4. **项目详情页的页面区改为两栏**：左栏分类目录（带页数），右栏当前分类的页面列表。分类口径与阅读页目录共用 `web/src/page-groups.ts`，避免同页在两处归到不同分类。
5. **抽屉只做一层**：抽屉内的确认框渲染在抽屉外面，并由 `paused` 暂停抽屉自己的 Esc 与焦点陷阱；确认框的层叠顺序必须高于抽屉与导入弹层。
6. **不新增导航项**：五栏导航不变，知识目录作为项目详情与阅读页的内部结构存在。

## 后果

- `PageReader.tsx` 不再承载结构编辑表单；`reader.css` 的 `.page-structure-actions` 随之删除。
- 新增 `components/Drawer.tsx`、`components/PageTree.tsx`、`page-groups.ts`。
- `.confirm-backdrop` 的 `z-index` 从 20 提到 60；否则抽屉里的确认框点不到。
- `ui-contract.allowlist.json` 增加 `PageTree.tsx` 的三条内部标识登记，`PageReader.tsx:page_id` 基线从 10 调到 11。
- 项目详情与阅读页的测试改为断言「目录 + 当前分类列表」，不再断言分组标题全部可见。
