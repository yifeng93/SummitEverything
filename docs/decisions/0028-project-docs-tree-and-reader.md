# ADR 0028：项目页改成「文档树 + 正文」，去掉中间的页面列表

日期：2026-10-29。状态：Accepted。用户指出项目页「左树 + 右列表」的两级结构没有意义：树里已经有分类，点分类只是把页面列到右边，看正文还要再点一次；要求树里直接包含文档，右侧直接显示 Markdown。此 ADR 只改项目详情页的文档区，不改数据、不做内容编辑。

## 背景

[ADR 0026](0026-page-tree-hierarchy.md) 把目录改成真实文件夹树后，项目页仍是「树选文件夹 → 右侧列页面 → 再点进整页阅读」三步。同一份层级信息被渲染了两遍（树、列表），而用户真正要看的是正文。窗口 1080px 时，列表还要再吃掉一屏宽度。

## 决定

1. **树里直接放文档**：文件夹节点（文件夹图标 + 子树篇数）之后跟着文档叶子（文件图标 + 标题），点击文档即在右侧渲染正文，不发生整页跳转。
2. **右侧复用阅读面板**：`PageReader` 增加 `pane` 模式——用外部传入的页面与项目数据、不渲染自己的左目录与返回行，其余（状态徽章、待确认的「确认当前版本」、页面操作、上一篇/下一篇）保持不变。这样确认与移动逻辑只有一份实现。
3. **默认展开当前文档所在路径**，其余文件夹收起；选中文档在树里高亮。
4. **去掉中间的列表**与它的元信息（日期、来源子目录）——树只回答「有哪些文档」，正文回答「这篇写了什么」。
5. 整页阅读（`PageReader` 非 pane 模式）保留，供今日、问答引用、审批等入口使用。

## 后果

- `ProjectDetailView` 删除列表渲染与 `timelineSummary`，新增 `activePageId`、`library`（全库页面与项目）、`onReloadPages`。
- `PageReader` 状态改为 `loadedProjects` / `loadedPages`，`pane` 有值时直接用外部数据，不再请求 `/projects`、`/pages`。
- 项目页宽度固定为 260px 树 + 1fr 正文；正文按 `--measure-read` 收窄（1080 时约 516px，1440 时 680px）。
- 依赖旧列表的测试改为断言树与右侧正文；渲染守卫扫描项目页时排除 `pre code`（代码按守卫 ⑥ 逐字保留）。
- 页面上不再显示每篇文档的可信业务日期；日期仍用于项目列表与排序。
